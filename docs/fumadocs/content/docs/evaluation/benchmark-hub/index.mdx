This hub is a **recipe index**, not a leaderboard site. Each card is generated from benchmark catalogs and task manifests: what the suite measures, which files it needs, and which WorldFoundry path is real (official import, in-tree scoring, or closed-loop). It does **not** invent ranks. Detail pages link a live author-maintained board when one exists, otherwise they cite the paper table or say so.

## How to pick a bench

Start from the claim you need to test, then open that recipe — do not install a dedicated environment first.

- **Lifelong / knowledge-transfer manipulation** — [LIBERO](/docs/evaluation/benchmark-hub/libero) (four suites on a Franka tabletop). Related kitchen work is [RoboCasa](/docs/evaluation/benchmark-hub/robocasa).
- **GPU-parallel skill families** — [ManiSkill](/docs/evaluation/benchmark-hub/maniskill) (SAPIEN). WorldFoundry imports rollouts; it does not replace the simulator.
- **Long-horizon language chains** — [CALVIN](/docs/evaluation/benchmark-hub/calvin) (A/B/C → D, success at chain length 1–5).
- **Real-to-sim policy ranking** — [SimplerEnv](/docs/evaluation/benchmark-hub/simpler-env) (Google Robot and WidowX/Bridge, calibrated to real setups).
- **Household activities with logical goals** — [BEHAVIOR-1K](/docs/evaluation/benchmark-hub/behavior1k) (1,000 BDDL activities in OmniGibson).
- **Whether a video model continues real physics** — [Physics-IQ](/docs/evaluation/benchmark-hub/physics-iq) (5-second continuations; in-tree scorer). Pair with [Physics-IQ Verified](/docs/evaluation/benchmark-hub/physics-iq-verified) only when that protocol is the one you mean — the media are not interchangeable.
- **Open T2V clip quality / composition** — [VBench](/docs/evaluation/benchmark-hub/vbench), [T2V-CompBench](/docs/evaluation/benchmark-hub/t2v-compbench), [FETV](/docs/evaluation/benchmark-hub/fetv).

Before installing benchmark-specific packages, read the [runtime environment matrix](/docs/evaluation/benchmark-hub/runtime-environments). It separates the unified environment, managed dedicated environments, hosted judges, and dimension-specific native/checkpoint stacks.

## How to run one benchmark

Open the recipe first. Prompt files, generated-artifact layouts, checkpoint names, judge models, and official result formats are benchmark-specific.

### Import official result files

Use this when the recipe says WorldFoundry **normalizes** an upstream export and does not run the simulator.

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id <benchmark-id> \
  --mode official-validation \
  --official-results-path <official-result-file-or-dir> \
  --generated-artifact-dir <generated-artifact-dir> \
  --output-dir tmp/<benchmark-id>/official-validation \
  --json
```

### Score generated artifacts in tree

Use `official-run` only when the recipe says the in-tree runtime can recompute scores from generated artifacts and the required media or checkpoints are staged. Physics-IQ is the usual example.

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id <benchmark-id> \
  --mode official-run \
  --generated-artifact-dir <generated-artifact-dir> \
  --output-dir tmp/<benchmark-id>/official-run \
  --json
```

To generate artifacts with a registered model before scoring:

```bash
worldfoundry-eval run \
  --benchmark <benchmark-id> \
  --model <model-id> \
  --mode official-run \
  --output-dir tmp/<benchmark-id>/<model-id> \
  --json
```
