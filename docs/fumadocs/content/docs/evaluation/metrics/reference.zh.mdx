## MetricRegistry

默认 registry 合并 `registry.py` 中的 `BUILTIN_METRIC_REGISTRY_ENTRIES` 与从 `worldfoundry/evals/tasks/metrics/{distribution,perceptual,scorer}/` 自动发现的 `METRIC_MODULE` 声明。

### 发现与查询

```bash
wf metric list
wf metric list --json

wf metric show fid
wf metric show clip-score --json

wf metric validate fid clip_score lpips laion_aesthetic has_artifact:generated_artifact
```

Registry key 大小写不敏感，下划线会归一化为连字符（`clip_score`、`clip-score`、`clipscore` 等价）。参数化 id 使用前缀：

- `has_artifact:<name>` — 示例：`has_artifact:generated_artifact`。指定 artifact 存在时返回 1。
- `numeric:<name>` — 示例：`numeric:reward`。从 result metadata/scores 读取名为 `<name>` 的数值字段。

### Python API

```python
from worldfoundry.evals.tasks.metrics.registry import (
    default_metric_registry,
    list_metric_registry_entries,
    validate_metric_ids,
    create_existing_results_metric,
)

for entry in list_metric_registry_entries():
    print(entry.id, entry.family, entry.aliases)

registry = default_metric_registry()
entry = registry.get("clip-score")
canonical = registry.canonical_metric_id("numeric:reward")

payload = validate_metric_ids(["fid", "unknown_metric"])
assert payload["ok"] is False

metric = create_existing_results_metric(
    metrics=["artifact_count", "has_artifact:video"],
    required_artifacts=["generated_artifact"],
)
```

FID、KID、Inception Score、precision/recall、MIND 和 `compute_distribution_metrics(...)` 接受图片目录或明确的图片文件列表。列表保留传入顺序，与目录使用相同的 RGB 转换和 `samples_resize_and_crop` 预处理。SwAV FID 也接受文件列表，并沿用自身的预处理及 `max_size` 上限。

内置后端通过 `worldfoundry.evals.tasks.metrics._shared.vendor.torch_fidelity` 加载，与已安装的 `torch_fidelity` 包及 TorchMetrics 的导入顺序相互独立。自定义特征提取器和噪声源需注册到该内置包。PPL 也接受已安装包中的 generator wrapper，保留其潜变量与类别元数据。

`compute_realism_score(...)` 接受生成图片目录、单张图片文件、数组或文件/数组序列。目录批处理为每张图输出一个 realism 分数，`mean_realism` 为其均值且与 batch size 无关。

Precision 表示生成样本被参考流形覆盖的比例，recall 表示参考样本被生成流形覆盖的比例。在 `compute_precision_recall(...)` 与 `compute_distribution_metrics(...)` 中，后端 `input1_*` 参数对应生成输入，`input2_*` 参数对应参考输入。批量接口也在生成集上计算 Inception Score。

`compute_ppl(...)` 返回后端的均值与标准差；设置 `ppl_reduction="none"` 时保留百分位过滤后的逐样本距离数组 `perceptual_path_length_raw`（`summarize_distribution_metrics(...)` 将其重命名为 `ppl_raw`）。PPL 默认取 1%–99% 百分位区间，可将 `ppl_discard_percentile_lower` 或 `ppl_discard_percentile_higher` 设为 `None` 单独关闭。

SceneFID manifest 的 key 可以是相对于图片根目录的路径或绝对路径。省略 `generated_bboxes_json` 时，参考 key 会按相对路径复用于生成目录，保留子目录层级；绝对参考路径必须位于参考根目录下。缺少图片时会报错，不会回退到其他同名文件。生成图片的文件名或 bbox 不同时，应提供独立的生成 manifest。

SceneFID、LQS 与 object-wise consistency 共用同一套 bbox 约定：四值表示 `(x1, y1, x2, y2)`，五值表示 `(x, y, width, height, extra)`，第五项不参与几何计算。像素坐标与归一化坐标使用相同格式；四值 `xywh` 输入需在调用前转换。

`JEDiMetric.load_features(num_samples=...)` 对缓存数组与新提取的特征使用相同的单侧样本上限；读取缓存不会截短磁盘上的文件。特征提取在本地运行，不创建或销毁分布式进程组，加载两侧特征后释放提取器。

JEDi 视频批次使用 `(B, T, C, H, W)`，像素范围为 `[0, 1]`；提取器先转换为通道在首维的视频片段，再执行归一化。Encoder 和 probe checkpoint 必须与模型匹配；缺少权重或形状不匹配时直接报错，不会保留初始化权重继续计算。

使用预计算特征时，`run_jedi_scorer(...)` 报告实际的 `reference_num_samples`、`generated_num_samples` 和 `feature_dim`。原有 `num_samples` 字段在两侧数量相等时记录共同数量，不相等时为 `null`。

Mock JEDi 后端直接用 UTF-8 seed 字节构造 NumPy 种子。相同 seed 和维度在独立进程中产生相同的特征与分数。

PSNR、SSIM、MS-SSIM 和 FSIM 保留输入像素尺度，两张图必须使用相同单位。任一输入是 uint8 或任一最大值超过 1 时，`data_range` 默认为 255，否则为 1。浮点像素值不足以判断预期值域时，应显式传入 `data_range`；该参数按原始单位传给后端。

LPIPS 接受 uint8 像素或 `[0, 1]` 归一化浮点数，使用 TorchMetrics 的 `normalize=True`。为兼容已有调用，任一浮点图像最大值超过 1 时，也按 `[0, 255]` 处理。两张图始终共用一个归一化尺度。

LQS 在每个类别内按最小总中心距离匹配对象（即使对象数量不同）。Recall 为匹配对象数除以真实对象数，precision 为匹配对象数除以预测对象数，位置与面积一致性在匹配对上计算，遵循 [LQS 定义](https://arxiv.org/html/2208.06162#S4.SS2.SSS2) 并由 SciPy 矩形指派求解。

- `wf metric list` — 列出或 JSON 导出全部 registry 条目。
- `wf metric show <id>` — 查看单条 entry、别名、参数化前缀。
- `wf metric validate <id>...` — 批量解析 id；未知 id 时 exit 1。
- `wf evaluate --metric ...` — **仅内置 existing-results 指标**（`artifact_count`、`required_artifacts_present`、`has_artifact:<name>`、`numeric`、`numeric:<name>`）。
- `wf plan create --metric ...` — 构造 run plan JSON 时使用相同内置 metric ID。

分布、感知与 scorer 指标通过 Python 调用。Benchmark runner 在计算官方 metric stack 时可能复用相同底层实现（EvalCrafter IS/FID、MiraBench FVD、VBench 美学评分等）。多模态 scorer（CLIPScore、VQAScore、ITMScore）通过 `worldfoundry.evals.tasks.metrics.get_score_model(...)` 暴露，实现位于 `execution/runners/_scorers/`。

## 依赖

安装 distribution-metrics extra 以使用 torch-fidelity、Clean-FID、CMMD、感知 torchmetrics 等：

```bash
pip install -e ".[distribution_metrics]"
```

`distribution_metrics` extra 核心依赖包括 `torch`、`torchvision`、`torchmetrics`、`scikit-learn`、`scipy`、`transformers`、`pillow`，以及 `pyproject.toml` 中声明的可选 metric 包。

重依赖保持 lazy import：导入 `worldfoundry.evals.tasks.metrics` 不应要求所有 checkpoint 已就绪，直到具体 `compute_*` 被调用。

修改指标时，请用有代表性的输入与上游实现比对分数，并记录后端版本和结果。私有指标回归测试未包含在公开仓库中。

## 架构

```
worldfoundry/evals/tasks/metrics/
├── __init__.py          # compute_* 与 scorer 入口的 lazy re-export
├── registry.py          # MetricModuleSpec、MetricRegistry、内置与自动发现的 entry
├── _shared/             # 跨 metric helper（torch-fidelity、CLIP、aesthetic、perceptual、CFID、pyiqa）
│   └── vendor/torch_fidelity/  # Vendored torch-fidelity（Apache-2.0）
├── distribution/        # 29 个分布家族包（fid、kid、inception_score、fvd、fvmd、jedi、cmmd、clean_fid 等）
├── perceptual/          # 13 个感知家族包（lpips、ssim、ms_ssim、psnr、dino_similarity、dreamsim、fsim 等）
└── scorer/              # 9 个 scorer 家族包（laion_aesthetic、facescore、artscore、facesim_cur、opens2v、semsr 等）
```

### 统一 metric 模块布局

每个已迁移的 metric 文件夹导出统一接口：

- `METRIC_ID`、`ALIASES`、`HIGHER_IS_BETTER`、`FAMILY`、`TAGS` — Registry 元数据
- `METRIC_MODULE` — 供 auto-discovery 的 :class:`MetricModuleSpec`
- `compute(...)` / `compute_<name>(...)` — 按 metric family 的稳定 compute API
- 论文 / 仓库链接 — 见 [指标配方子页面](/zh/docs/evaluation/metrics) 各 metric 小节内联说明

已迁移 metric 的 registry entry 通过 `registry.discover_metric_registry_entries()` 注册，而非在 `registry.py` 中硬编码重复项。目录分组（`distribution/`、`perceptual/`、`scorer/`）与各包向 `registry.py` 声明的 `family` 保持一致。

### Import 入口

顶层 `metrics/__init__.py` 从 `distribution/`、`perceptual/`、`scorer/` 与 `execution/runners/_scorers/` 懒加载 re-export `compute_*` 函数和模块别名，同时支持 `from worldfoundry.evals.tasks.metrics import compute_fid` 与按家族路径导入（如 `from worldfoundry.evals.tasks.metrics.distribution.fid import compute_fid`），不会触发重依赖提前加载。

Benchmark catalog metric 与官方结果归一化在 `execution/runners/` 完成；benchmark-specific 配置应写在对应的 [Benchmark Hub](/zh/docs/evaluation/benchmark-hub) 子页面。
