## 本层职责

TUI、CLI、Studio、Python、MCP 是操作同一系统的不同方式，都不承载模型推理或 benchmark 打分。它们的任务是把用户意图转换为执行层能够识别的某一种 request 类型，并展示结果。本页覆盖 CLI/TUI、Studio 入口、MCP，以及把意图编译为可运行 plan 的编排服务。

request 产生之后落到哪里，先读 [工作流](/zh/docs/maintainers/architecture/workflow)。实际执行的 delegate runner 见 [评测核心](/zh/docs/maintainers/architecture/evaluation-core)。

## CLI 与 TUI

控制台入口是 `worldfoundry/cli/main.py:304` `main()`。它在 `cli/main.py:183` 起构建子命令树：

- **`tui`** —— 启动引导式发现 TUI。TUI 在 `cli/tui/` 包里（`__init__.py` 注册 `wf tui` 及其参数，`launcher.py` 的 `run_tui` 在 `:29` 分派动作，另有 Textual `app.py`、表单 `controls.py` 与 brand/logo/icon 助手）；它与 MCP 共用的 catalog 行、推理变体与命令构建分别在 `cli/catalog.py`、`cli/inference_variants.py`、`cli/command_builders.py`。它驱动与 CLI 相同的 catalog 与编排调用，只是展示，不是第二套 runtime。
- **`evaluate`** —— 归一化输入、选择 run mode、返回一个 `EvaluateRunResult`。
- **`run`** —— 直接运行模型；带 `--benchmark` 时通过统一 benchmark facade 生成并打分。
- **`validate`** —— 不跑模型即校验 benchmark metadata 加载。
- **`embodied`** —— 具身评测子树（`run`、`serve`、`merge`、`plan`）。
- 另有 `zoo`、`models`、`preflight`、`dataset`、`tasks`、`suites`、`task`、`config`、`plan`、`metric`、`score`、`generate-score`、`reproduce`、`compare-runs`、`index-runs`、`validate-artifact` 与 `mcp`。

CLI 将命令调度到编排服务，不直接 import pipeline 文件或算 metric。保持这一点，才能在不重新实现生成、artifact 物化或打分的前提下新增界面。

Studio 是交互式预览界面，安装入口是 `worldfoundry/studio/cli.py:21` `main()`。它复用同一套 catalog 与 runtime 契约，不承载打分。内部结构见 [Studio 内部](/zh/docs/maintainers/architecture/studio-internals)。

## MCP

MCP server 把 catalog、run 生命周期、metric、readiness 暴露为工具，让 agent 驱动同一工作流。它是复用同一套契约的薄壳，不含私有模型代码。

- 入口：`mcp/__init__.py:43` `main()`；server 构造在 `mcp/server.py`（`create_mcp_server` `:43`、`run_server` `:58`）。
- 每个 payload 用 `@mcp_tool`（`mcp/tools/spec.py:64`）声明一次；`mcp/tools/registration.py:19` `register_tools` 调用 `bind_tools`（`spec.py:130`），把每个 spec 注册为带行为注解的异步 FastMCP 工具。
- 工具 payload 按职责分组，而非按模型：`discovery`（list/get model、benchmark、task）、`runs`（preview、evaluate、status、result、samples、cancel）、`metrics`（list、show）、`readiness`（benchmark dataset 检查）、`studio`（workspace 推理）、`context`（`MCPToolContext`）。

因为每个工具都经同一 catalog 与编排服务解析，MCP 驱动的 run 与 CLI 驱动的 run 产出相同的 artifact 与 scorecard。

## 编排服务

编排服务是界面与执行之间唯一的编译边界，位于 `evals/tasks/execution/orchestration/service.py`。它校验五个 intent dataclass 之一，返回执行层可运行的 `PreparedEvaluation`。

## 三个规划边界

WorldFoundry 保持三种规划类型相互独立。不要用第四种 recipe executor 包裹它们。
