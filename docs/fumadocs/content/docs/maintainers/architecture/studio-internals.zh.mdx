Studio 是覆盖同一套 pipeline 与 artifact 契约的目录驱动 shell，供 CLI 推理与评测共用。它不拥有模型权重、打分逻辑或 benchmark manifest；职责是发现可运行条目、准备输入、调用正确的 runtime driver、写出 `RunRecord`，并为 UI 挑选 preview assets。同一套执行核心服务 `world` 实时交互页面、Workspace job、conda 子进程与 torchrun worker。

<ArchDiagram id="studio" locale="zh" />

会话编排放在 `studio/inference/execution.py`，catalog 发现放在 `studio/inference/catalog.py`。模型输入语义与生成状态由公开 pipeline 及其 operator 持有。`studio/ui/launcher.py` 负责独立前端路由，启动参数由 `studio/ui/launch_config.py` 解析。页面、全屏与键盘交互位于 `studio/visualization/backends/world.py` 和 `world_realtime_client.py`。

## Catalog discovery

Catalog 构建刻意做成静态过程。`discover_catalog()` 用 AST helpers 扫描 pipeline 模块，从而在不 import 重型 CUDA 栈或可选依赖的情况下列出模型。它合并三路来源：`pipeline_*.py` 类、component-pipeline 工厂、action-synthesis 类，再叠加 curated overrides 与 canonical runtime entries（aliases、默认 kwargs、checkpoint、`runtime_kind`）。去重键是 `(module_path, class_name)`；隐藏或抽象 id 不会进入 UI 列表。

单模型 `find_entry()` 与完整列表使用相同的 canonical runtime 默认值，包括别名、prompt/参考图配对、checkpoint 覆盖和 call/load 选项。查找先筛选 canonical 条目，再解析 checkpoint 路径，不探测无关模型的 checkpoint。Sana 和 CogVideoX 的 checkpoint 变体仍解析到各自的共享 Studio 卡片；具体执行使用 `find_runtime_entry()`。

真正的 import 发生在更晚：只有某次 run 需要具体类时，`StudioManager.import_pipeline_class()` 才按 `CatalogEntry` 的 `module_path` / `class_name` 加载。因此模型可以出现在 catalog 里，却在 LOAD 时因当前环境缺少 runtime import 或本地 checkpoint 而失败。

- **找 project root** (`_project_root()` / `_project_root_candidates()`) — 允许 Studio 从 repo root 或 package context 运行。
- **检查 pipelines**（`_AstPipelineInfo` 周边 AST helpers）— 不 import 重型模型依赖，直接读取 pipeline modules。
- **归一化 ids** (`_normalize_model_id()`) — UI、CLI launch args 和 recent runs 共用的稳定 lookup key。
- **构建 entries** (`discover_catalog()`) — 产出 `CatalogEntry[]`，包含 family、class path、category、backend、aliases、examples。
- **过滤 entries** (`filter_catalog()`) — 对 UI 列表应用 search 和 category filters。

## Execution core

`StudioManager` 是编排中枢。典型的 `run` / `stream` / `init` / `reset` 路径会准备 request、把输入落到 run 目录、按 `entry.runtime_kind` 选择 driver、加载 pipeline（LRU 缓存）、调用 driver，再物化为 `RunRecord`。Driver 存在是因为并非每个家族都是一次 `__call__`：two-stage 3DGS 先重建再 orbit，point-cloud nav 先重建再渲染视角。WorldFM 走 `BaseRuntimeDriver`；相机控制与标定由 operator 负责，场景重建与 streaming state 由 pipeline 持有。

`PreparedInputs` 是 staging 后的归一化载荷（prompt、图像、视频、interactions、runtime kwargs）。`PipelineContext` 保存已加载类、device、variant 与 output root。`RunRecord` 是 UI 可重载的持久单元：ids、inputs、outputs、artifact 路径、preview 选择、status 与 manifest JSON。Workspace 推理还可传入 `infer_metadata` 契约，让物化阶段校验必需的输出类型（video、image、splat 等）。

- `PreparedInputs` — 保存 staged prompt、images、videos、interactions、runtime kwargs 和 metadata。
- `RunRecord` — 保存 run ID、model ID、inputs、outputs、artifacts、preview paths、status 和 manifest export。
- `PipelineContext` — 保存 imported pipeline class、model ref、device、variant、load kwargs、output root。
- `BaseRuntimeDriver` — 默认 driver：load pipeline、run fresh request、可选 initialize/continue streaming、reset state。
- `TwoStage3DGSRuntimeDriver` — Two-stage 3DGS flows 的专用 driver。
- `PointCloudNavRuntimeDriver` — Point-cloud/navigation previews 的专用 driver。
- `StudioManager` — 编排 import、driver selection、input preparation、run execution、recent-run storage、unload/reset。

## Pipeline 持有的交互状态

提供 `stream_state_ready()` 的 pipeline 持有自己的交互状态。共享 driver 直接转发输入，不向其 memory 填入原始图像，也不以生成帧替换模型 context。可选的 `init_stream(...)` 沿 pipeline 的输入契约初始化状态，不生成 chunk。未提供这些方法、使用 frame memory 的 pipeline 仍走共享图像初始化路径。Native visual adapter 保存的是产物历史，不是可复用的 rollout 状态：`stream_state_ready()` 始终为 false，每次 stream 请求保留自己的显式 conditioning。内存 keyframe 使用与传输相同的声明 layout 和像素值域。

普通 action、实时 fallback 与 torchrun 各 rank 共用 `BaseRuntimeDriver.initialize_stream()` 和 `continue_stream()`。实时与 worker 初始化不物化 preview；分布式产物导出由 rank zero 负责。原生实时 pipeline 保留 `prepare_realtime()` / `configure_realtime()` / `stream_realtime()`。会话 reset 和缓存模型 reset 都优先调用 `reset_realtime()`，其次 `reset_memory()`，最后才是 frame-memory reset。几何 driver 保留重建/渲染状态转换，无状态/API 调用不获得 streaming state。

`WorldFMPipeline.init_stream()` 重建并记录场景，随后 `stream()` 复用它。重建失败时保留原场景；reset 清除当前实例的 scene memory。`WorldFMOperator` 接受显式 pose 或 navigation token，采用世界坐标平移与局部 Rx/Rz 旋转，并按显式 `K`、meta 文件 `K`、源图像默认值的顺序解析标定。Studio 负责 staging，不实现这些模型数学。

Torchrun command bridge 负责 rank/device 映射、collective 顺序和进程清理。`PreparedInputs.explicit_load_params` 在 worker 传输中保留用户覆盖的参数名，避免把启动默认值误当成显式 loader 选择。LingBot 的复制/FSDP、offload、sequence-parallel 默认值与实际进程数策略位于 `pipelines/lingbot_world/distributed.py`。Matrix-Game 3、LongVie 2、Helios 和 DreamX 保留各自的 topology 与加载契约。

回归覆盖 pipeline 持有的 INIT/STREAM/RESET、初始化失败及重试、A/B/A 实例隔离、公开 loader 委托、frame-memory 初始化、缓存租约和 torchrun 策略隔离。无权重契约与 accepted-reference checkpoint 回放、实时性能门禁分开验收。

## Preview 和 Artifact Helpers

Driver 返回后，`materialize_run()` 把异构 result 落成 run 目录下的文件：metadata JSON、已知 artifact key、可选的 frame→video 导出、mesh 转换，以及可选的 Rerun recording。若 preview 仍为空，Studio 可能按 `WORLDFOUNDRY_STUDIO_ARTIFACT_SCAN_MODE` 扫描输出目录。随后 `pick_preview_assets()` 为 UI 排序生成产物，返回主视频、图像、splat/model、gallery 与可选 `.rrd`。Fresh 与 streaming 物化从 preview 选择中排除 staged inputs 和显式 conditioning 路径。仅初始化状态的 INIT 可以展示 seed image，但输入附件不能满足必需的生成输出类型。输入仍保留在本次 run 持有的 staging 目录。

Preview 空白通常意味着 pipeline 把文件写到了预期 key 之外、返回了没有 `save()` 的内存对象，或产出了解码器拒绝的视频。应先修 pipeline 契约，再考虑放宽 scan mode 或转换 helpers。

- `export_frames_to_video()` — 把 frame sequences 转成 preview video。
- `collect_artifact_paths()` — 在 output directory 下发现生成文件。
- `pick_preview_assets()` — 为 UI preview 选择 primary video/image/model/json assets。
- `maybe_extract_video_preview_image()` — 从 video preview 保存代表性图片。
- `convert_model_for_preview()` — Browser preview 需要别的格式时转换 3D assets。
- `maybe_build_rerun_rrd()` — 可用时构建 Rerun recording。
- `write_json()` — 写 run manifests 和 input/output records。

## UI 文件边界

启动与展示通过独立浏览器前端提供。模型加载、输入归一化、runtime driver 与 artifact 契约由共享推理模块负责，页面与传输层调用 `StudioManager`。

- **启动参数** — `ui/launch_config.py` 解析 CLI flags 与环境默认值，返回 `StudioLaunchConfig`。
- **前端路由** — `ui/launcher.py` 与 `visualization/backends/frontends.py` 根据模型或 artifact 启动 `world`、Viser、Spark 等前端。
- **浏览器交互** — `visualization/backends/world.py` 与 `world_realtime_client.py` 负责页面、全屏、键盘和摇杆。
- **实时传输** — `visualization/backends/world_realtime.py` 维护常驻会话，调用 `StudioManager.run_realtime()` 并通过 WebRTC/WebSocket 传输帧和控制。
- **共享推理** — `inference/execution.py` 负责会话编排、pipeline 缓存租约和 driver 调用；模型执行与状态由 pipeline 持有。实时交互直接传输内存中的帧，每次按键无需导出 MP4。

## 实时服务边界

实时路径刻意把模型状态与展示状态分开：

<ArchDiagram id="studio-realtime" locale="zh" />

模型通过 `RealtimeSpec` 拥有因果时序；transport 不应猜测 latent stride，也不能
静默改变严格 segment 帧数。`latest-interactive` 会在有界 backpressure 后丢弃旧帧，
保护控制延迟；`ordered-quality` 从不丢帧，凡是 `chunk_done` 帧数属于播放契约的
prompt-scheduled 或 queued segment 都必须使用它。

Native visual 解码结果通过已有 core `VideoChunk` 携带 `video_chunk`：显式 layout、像素值域与由 layout 推导的帧数。图像输出使用长度为一的时间轴。Native 的 fresh/stream 调用在 `return_dict=True` 时保留这些语义，原始返回仍为 tensor 或产物路径。Studio 优先读取该 chunk，而非无类型别名，并复用 `core/media/codecs/video.py` 转换；即使 `[-1,1]` 输出片段全部为正值，也按声明的有符号像素处理。单视频传输要求 batch/view 轴长度为一；多视角由 sensor composition 合成。CUDA byte chunk 沿用设备快照与 event 传输。

Postprocessor 位于解码 RGB 提取之后，持有隔离的会话状态，可以暂存一个 chunk，
并按 chain 顺序 flush 尾帧。默认 identity processor 也走同一条生产边界但不改变
输出，因此未来接 VSR、去噪或插帧时不需要侵入模型专属推理循环。RTX adapter
保持 layout/container/dtype/range，每条 stream 独占一个 VFX effect，复用前先 clone
借用的 DLPack 输出，并由单独授权的 `rtx_postprocess` extra 控制。每个完成的 chunk
都会记录归一化阶段 timing；用 `runtime/realtime_regression.py` 可以对 trace 中的
p50/p90、吞吐、队列深度和掉帧做门禁。

## 调试路径

多数 Studio bug 来自 catalog、输入、runtime 或 artifact 契约错位。缺模型几乎总是 catalog discovery、aliases 或隐藏 id。device / variant 错通常来自 launch config 与 `PipelineContext` overrides。输入到不了模型，问题在 `prepare_inputs()` 或 driver kwargs 绑定。Streaming 失败常见于没有 memory state 就调用 `init`/`stream`，或 two-stage driver 尚无先验重建。Recent run 无法 reload，说明 `materialize_run()` 之后 manifest 或 artifact 路径漂移了。

- **UI 里缺模型** — `discover_catalog()` output、`CatalogEntry.aliases`、category filter、pipeline file naming。
- **Variant/device 错** — `StudioLaunchConfig`、`resolve_cli_variant_id()`、`PipelineContext`。
- **输入没到模型** — `prepare_inputs()`、`PreparedInputs`、driver `run_fresh()` kwargs。
- **Preview 空白** — `collect_artifact_paths()`、`pick_preview_assets()`、conversion helpers、generated file extension。
- **Streaming 坏了** — `BaseRuntimeDriver.run_init()`、`BaseRuntimeDriver.run_continue()`、pipeline `stream()`、memory state。
- **Recent run 无法 reload** — `RunRecord.to_manifest()`、`materialize_run()`、`load_run()`、artifact paths。
