## 介绍

WorldFoundry Studio 是围绕仓库 pipelines 的薄可视化入口。模型在启动时固定；切换模型族时启动新进程。

Studio 现在有多前端入口：

- **`world`** — 交互世界模型。独立 WebRTC 控制台：常驻模型、可靠按键边沿 DataChannel、有界内存帧队列、单一持续视频轨、沉浸式全屏和实时运行日志；控制热路径不生成 MP4。
- **`points`** — Viser 点云 / mesh。直接启动原生 Viser，不嵌回游戏机界面。
- **`embodied`** — 具身智能仿真器。**计划中。** 目前只是 URL bridge：Studio 登记外部 simulator URL 并给出 tunnel 提示，还没有仓内 embodied viewer。
- **`spark`** — 3DGS。启动独立 Spark 3DGS viewer，复用项目内置 Spark frontend，并允许通过 `WORLDFOUNDRY_MODEL_DIR` / `WORLDFOUNDRY_ARTIFACT_DIR` 暴露本地资产。
- **`unified`** — Gradio 壳。需要 `worldfoundry[ui]`；Workspace 会隐藏该 visualizer 模式。
- **`auto`** — 默认。按模型类型自动路由：交互世界 -> `world`，3D scene -> `spark`，点云/深度 -> `points`，具身策略 -> `embodied`。

## 可视化内容

- **Preview Video** — 最新生成或 streamed video。
- **Preview Image** — Still-image outputs 和 imported reference frames。
- **3D World** — 导出时显示 Gaussian splat、point cloud 或 spatial outputs。
- **Gallery** — 最近 shots 和 preview artifacts。
- **Artifacts** — 用于检查和下载的 raw output artifacts。

默认情况下，Studio 会隐藏大多数高级面板。使用 `--show-aux-panels` 显示 history、notes、catalog、3DGS import 和低层 runtime controls。

## Workspace 模式

多模型验证和发布 QA 推荐启动 workspace app，而不是单模型 Studio 进程：

```bash
source tmp/worldfoundry_unified_env.sh
conda activate "${WORLDFOUNDRY_UNIFIED_ENV_PREFIX}"
```

```bash
bash scripts/workspace/run_workspace.sh \
  --host 127.0.0.1 \
  --port 7870 \
  --max-jobs 8
```

如果 checkpoint 或 benchmark 数据不在默认 cache 中，显式传入根目录：

```bash
bash scripts/workspace/run_workspace.sh \
  --ckpt-dir /path/to/checkpoints \
  --data-dir /path/to/benchmark-data
```

launcher 不依赖任何机器专有路径。资产解析顺序是：命令行参数、已经导出的
环境变量、repo 同级存在的 `ckpt/` 或 `data/` 目录、`tmp/worldfoundry_unified_env.sh`
中的 env-file 值，最后回退到 `~/.cache/worldfoundry/...`。

首次 CUDA 安装与[快速开始](/zh/docs/quickstart)相同，使用官方脚本 `bash scripts/setup/bootstrap_worldfoundry.sh`。
Workspace 必须从模型推理使用的统一 runtime 环境启动，不能从只装了 UI
依赖的轻量环境启动。CUDA 12.8 机器通常对应
`worldfoundry-unified-cu128`，先执行 `source tmp/worldfoundry_unified_env.sh`
再启动 `7870`。如果 **LOAD** 或 **START** 报 `cv2` 等模块缺失，说明当前
`7870` 进程不是统一 runtime 环境，先重启 workspace，再排查模型代码。

不要在机器之间复制或搬迁已经创建好的 conda 环境。Python、OpenSSL 等原生
链接可能仍指向旧 prefix，导致浏览器服务能启动，但 resident inference worker
一运行模型就报缺少 `python3.x`、`cv2`、`libssl` 或 `libcrypto`。遇到这类
问题，按公开 setup 路径验证或重建统一环境：

```bash
bash scripts/setup/bootstrap_worldfoundry.sh --verify-only
source tmp/worldfoundry_unified_env.sh
bash scripts/workspace/run_workspace.sh
```

打开：

```text
http://127.0.0.1:7870/
```

workspace 是发布验证时推荐使用的 UI。
它适合提交 inference job、检查不同模型的输入表单、查看生成产物，
以及在同一个界面里对比多次 run。
这些 Workspace job 是视觉冒烟（`python -m worldfoundry.studio.workspace_job infer`）。日常可复现 / 模型页命令用 `worldfoundry-eval run <id> --pipeline.task-profile …`。入口对照见 [CLI 命令入口](/zh/docs/reference/cli#命令入口)。

Workspace 也支持 evaluation job。以 VBench 为例：选择 **Evaluation**，
benchmark 选 `vbench`，把生成视频目录填到 **Dataset Root**（或把官方
VBench results JSON 填到 **Results Path**），**Metrics** 填一个或多个
dimension，例如 `aesthetic_quality`、`motion_smoothness`，也可以填 preset
`custom_supported`。VBench 专用 runtime 参数，例如
`{"mode":"custom_input","load_ckpt_from_local":true}`，写到 **Eval Runtime JSON**。

### Create Job 配置

Workspace UI **没有单独的 Settings 页**。每次提交前在 **Create Job** 对话框里
定制参数即可。

- **Model / variant / task profile** — 选择 catalog 条目，以及该模型暴露的官方输入 contract。
- **Prompt、input path、动态 task 字段** — 来自 inference contract 的模型专用输入。
- **Device、backend、attention** — 运行设备与加载路径（`auto`、`from_pretrained`、`api_init`）。
- **Frames、FPS、height、width、steps、guidance、seed** — 写入 job payload 的生成参数。
- **Runtime checks** — 可选内存/编译开关，例如 Torch Compile、CPU Offload、VAE Offload、Text Encoder Offload；仅在所选模型声明支持时显示。
- **Call JSON / Load JSON** — 合并进 `call_kwargs` 和 `load_kwargs` 的高级 override。

打开 **Create Job** 或切换 task profile 时，表单会先用 Workspace 启动时加载
的默认值预填。catalog 和 task profile 中的模型专用官方 demo 值仍优先于这些
共享默认值。

### 可选的持久化默认值

若希望在 Workspace 重启后仍复用同一套默认值，可指定 JSON settings 文件：

```bash
export WORLDFOUNDRY_STUDIO_SETTINGS_FILE=/path/to/studio-settings.json
```

启动时 Workspace 会把该文件加载到 `/api/settings`，Create Job 表单通过
`GET /api/settings` 读取。运维脚本也可以用 `POST /api/settings` 更新：

```bash
curl -sS -X POST http://127.0.0.1:7870/api/settings \
  -H 'Content-Type: application/json' \
  -d '{"values":{"fps":12,"num_frames":49,"attention_backend":"torch"}}'
```

未设置 `WORLDFOUNDRY_STUDIO_SETTINGS_FILE` 时，默认值只存在于当前 Workspace
进程内存中，重启后会恢复为内置默认。

为了让 job 完成路径最快，模型 runtime 应该在 run record 中显式返回
`preview_image`、`preview_video`、`artifact_paths`、`rrd_path` 和 `output_dir`。
只有旧 runtime 只写文件、不返回路径时，才建议把 artifact scan mode 切到
`always`。

Resident worker 会让 conda 子进程在多个 job 之间保持存活，因此子进程里的
`StudioManager` 可以复用 pipeline cache。排查进程启动问题，或希望每个 job
结束后立刻释放 GPU 显存时，设置 `WORLDFOUNDRY_STUDIO_RESIDENT_WORKERS=0`。

**Visualizers**、**Gallery** 和 **Artifacts** 适合快速视觉 QA。
这些视图会展示最近生成的视频、图片、manifest 和直接 artifact 链接。
真正对外声明验证通过前，还需要把对应 run 记录到模型推理验证页。

## Workspace 可视化入口

`7870` Workspace 是整套可视化服务的统一浏览器入口。打开 **Visualizers**
页面后，每张卡片都有 **Launch**、**Open** 和 **Stop** 按钮。卡片下方会
嵌入正在运行的 viewer iframe，普通 QA 流程里不需要手动复制 URL。

具身仿真器不是 Workspace visualizer。`--frontend embodied` 只会登记外部
simulator URL 并打印 tunnel 提示；请先单独启动 simulator，再传入
`--simulator-url`。

`world` 默认使用 `7868`。只有部署环境要求固定代理路由时，才需要手动指定端口。

实时前端需要 `worldfoundry[studio_realtime]`（`worldfoundry[ui]` 已包含）。
服务启动时会后台加载模型；一次会话固定复用同一个 pipeline context 和执行线程。
WASD/IJKL 只发送按下/释放边沿，服务端按生成 chunk 重采样；RGB 帧直接进入
WebRTC 视频轨。控制到画面的热路径不会扫描 artifact、写 manifest 或编码 MP4。

### 可选 NVIDIA RTX 后处理

RTX Video Super Resolution 不进入模型的因果状态：它只在 transport 前处理已经
decode 的 RGB 帧，并保持帧数、顺序、dtype 与数值范围不变。Studio 会把处理后的
尺寸作为 transport 的 **Native** 分辨率，并从它推导更小的传输选项。由于 `nvidia-vfx`
使用 NVIDIA 专有许可证，它不会进入默认依赖或 `all` extra，必须显式安装和启用：

```bash
pip install 'worldfoundry[studio_realtime,rtx_postprocess]'

export WORLDFOUNDRY_REALTIME_POSTPROCESS_PRESET=rtx-super-resolution
export WORLDFOUNDRY_REALTIME_RTX_SCALE=1.5
python -m worldfoundry.studio.ui.gradio_app <model-id> --frontend world --device cuda:0
```

服务启动前，adapter 会检查 package、CUDA 可见性、device index、Turing 或更新
架构的 compute capability，以及 Linux NGX driver library；随后还会加载所选 native
effect 并处理一帧代表性输入，因此 driver image 不完整时会在 Studio 对外服务前失败。
真正调用时，backend 收到连续的 CHW `float32` CUDA 帧（范围 `[0, 1]`）；每次调用后
会先 clone 借用的 DLPack 输出，再复用 effect。不启动 Studio 也可以分别执行静态检查
和完整 native probe：

```bash
python -c 'from worldfoundry.core.video.rtx import inspect_rtx_vfx_capability as check; print(check(device=0).to_payload())'
python -c 'from worldfoundry.core.video.rtx import probe_rtx_vfx_runtime as probe; print(probe(device=0).to_payload())'
```

Linux 上的 `VideoSuperRes` 还需要 `libnvidia-ngx.so.1`。即使 CUDA 与 `nvidia-smi`
正常，compute-only/headless driver image 也可能省略它。请从与当前 driver **完全相同
版本**的 NGX/OpenGL userspace 组件（通常为 `libnvidia-gl-<driver-major>`）安装该库，
并在 Python 启动前让 dynamic linker 可见；不要混用不同 driver 版本的库。

支持的 OS 与 driver 版本由 NVIDIA 决定，部署前应核对最新的
[NVIDIA VFX Python requirements](https://pypi.org/project/nvidia-vfx/)。VSR 会增加
transport 像素量和 `postprocess_ms`，因此应按下方门禁做 A/B trace。低延迟交互建议
从 1.5x `HIGH` 起步；只有实测 GPU 仍有余量时再启用 `ULTRA` 或 2–4x。
`rtx-deblur-ultra` 保持原分辨率，不会增加传输带宽。

### 实时性能回归门禁

先启用原始 timing，完成一次有代表性的交互，再用显式 JSON manifest 检查
最后一个匹配会话。Warmup chunk 会保留在 trace 中用于诊断，但带 `warmup=true`
的记录不会进入统计。

```bash
export WORLDFOUNDRY_REALTIME_PERF_JSONL=outputs/realtime-timing.jsonl
export WORLDFOUNDRY_REALTIME_PERF_WARMUP_CHUNKS=1
```

```json title="realtime-regression.json"
{
  "schema_version": "worldfoundry-realtime-regression-v1",
  "cases": [{
    "name": "lingbot-webrtc",
    "selectors": {"model_id": "lingbot-world", "transport": "webrtc"},
    "thresholds": {
      "min_chunks": 10,
      "min_throughput_fps": 16,
      "max_dropped_frames": 0,
      "max_queue_depth": 16,
      "max_stage_p90_ms": {"generation_ms": 650, "model_ms": 500}
    }
  }]
}
```

Python 调用方可使用 `worldfoundry.runtime.realtime_regression` 中的
`RealtimeRegressionManifest.read_json()` 加载此文件，使用
`read_realtime_trace()` 读取 trace，再将两者传给
`evaluate_realtime_manifest()`。结果包含每个实际值、比较符和阈值，
也可转换为统一的 `PerformanceManifest`。

远程机器上使用时，需要暴露 `7870` 和实际启动的 viewer 端口。例如：

```bash
ssh -L 7870:127.0.0.1:7870 \
    -L 18590:127.0.0.1:18590 \
    -L 8765:127.0.0.1:8765 \
    -L 9876:127.0.0.1:9876 \
    user@host
```

## 产物可视化路由

inference job 完成后，Workspace 会扫描 run record 和输出目录里的可视化产物。
**Artifacts** 页会为支持的文件显示 **Open** 和 **Open in ...** 操作。
**Job Detail** 只保留内嵌 preview video/image，不再重复 viewer 快捷入口。

- **`.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.bmp`, `.mp4`, `.mov`, `.webm`, `.mkv`, `.avi`, `.wav`, `.mp3`, `.flac`, `.ogg` media files** — Workspace 内联预览和直接 **Open** 链接
- **`.ply`, `.pcd`, `.xyz`, `.glb`, `.gltf`, `.obj` geometry files；包含可解释 geometry/depth key 的 `.npz`** — Viser Geometry Viewer
- **`.splat`, `.spz`, `.ksplat`, `.sog` 和 Gaussian-splat `.ply`** — Spark Gaussian Splat Viewer
- **`.rrd` recordings** — Rerun Timeline Viewer

### Base model 感知结果

WorldFoundry 为仓内 3D 和 perception model 维护一份统一的可视化能力注册表。
编写 model-specific viewer 前先查询注册表：

```bash
worldfoundry-eval models visualizations
worldfoundry-eval models visualizations --family perception_core
worldfoundry-eval models visualizations --model raft --json
```

结构化 2D 结果复用同一个转换命令。当前支持 `detection`、`mask`、`flow`、
`tracks`、`feature-pca`、`depth`、`normal`、`keypoints` 和 `text`：

```bash
worldfoundry-eval models visualize \
  --kind flow \
  --artifact outputs/flow.npz \
  --output outputs/flow.png

worldfoundry-eval models visualize \
  --kind detection \
  --artifact outputs/detections.json \
  --media inputs/frame.png \
  --output outputs/detections.png
```

这条共享路径覆盖 Depth Anything、SAM、RAFT、DINO、GroundingDINO、
YOLO World、CoTracker 等仓内 family 的官方输出 schema。原生图像/视频进入
media viewer，点云和 mesh 进入 Viser，Gaussian splat 进入 Spark，同步场景记录
进入 Rerun。每个模型的权威映射以 registry 命令输出为准。

对磁盘上已有的 run，直接在 Workspace 打开该 run，用 **Artifacts** 标签页确认
viewer 路由。上表是路由参考；具体 run 以 Artifacts 里的 **Open** / **Open in ...**
按钮为准。

对模型作者来说，最容易复现的方式是把输出写到 Studio run 的输出目录，并在
run record 中保留稳定路径：

- `preview_image` 或 `preview_video`：用于快速媒体预览。
- `artifact_paths`：用于原始生成产物。
- `rrd_path`：用于 Rerun recording。
- `output_dir`：用于让 Workspace 继续发现目录里的其他文件。

3D reconstruction 模型应该导出浏览器可读的 `.ply`、`.glb`、`.gltf`、`.obj`、
`.pcd`、`.xyz` 或紧凑点云/depth `.npz`。3DGS 模型应该导出原生 splat 文件，或者
header 中包含 scale、rotation、opacity、spherical-harmonic color 等 splat
属性的 binary little-endian Gaussian-splat PLY。Workspace 会在选择 Viser 或
Spark 前区分普通 PLY geometry 和 Gaussian-splat PLY。

### 坐标系契约

启动 viewer 是 geometry contract 的一部分。points、mesh、camera-to-world、frustum
和 trajectory 必须处于同一个已声明坐标系，不能只翻转点云：

- 已完成 OpenCV-to-OpenGL 对齐的官方 GLB 使用 `asset-native` 和 exporter 声明的
  up axis；VGGT/VGGT-Omega 官方 GLB 使用 `+Y` up、`alignment=none`。
- VGGT/VGGT-Omega、UniDepth V2 与 UniK3D 的原始 model-point NPZ 保留 OpenCV
  camera frame，Viser 只应用一次 `opencv-to-opengl` 并使用 `+Y` up。
- UniDepth V2/UniK3D 的 Workspace PLY 已写成 `x-right/y-up/z-forward`，因此使用
  `asset-native`、`+Y` up、`alignment=none`，不能再次翻转。
- DUSt3R、LoGeR 与 Pi3 的 PLY 保留预测 camera-to-world sidecar；Viser 对 points
  与 cameras 一起应用 `first-camera-opengl`，使用 `+Y` up，并按中心 5-95%
  geometry 取景，避免少量离群点把有效场景缩得过小。
- Rerun recording 必须声明 world `ViewCoordinates`，并让每个 `Pinhole` 使用同一
  camera convention；Cut3R 与 MonST3R 的 world/camera 都使用 RDF。

Workspace 会自动解析 VGGT、DUSt3R、LoGeR、Pi3、UniDepth V2 与 UniK3D 的上述已验证默认值。其他 exporter 可用 Visualizer Params JSON
显式覆盖。请求端口被占用时，Viser 会显示实际绑定端口。Rerun 默认使用 WebGPU；
只有目标浏览器需要时才设置 `WORLDFOUNDRY_STUDIO_RERUN_RENDERER=webgl`。

### 选择 3D viewer

默认按产物语义路由，避免每个模型重复实现 viewer：

- **静态点云、mesh、depth-derived geometry、camera frustum** — 默认 viewer Viser。何时保留官方 viewer：存在共享 scene layer 无法表达的模型专用控制或标注。
- **时变 geometry、camera trajectory、同步 image/depth/action** — 默认 viewer Rerun。何时保留官方 viewer：导出为 `.rrd` 会丢失官方 timeline 语义。
- **Gaussian splat** — 默认 viewer Spark。何时保留官方 viewer：上游依赖非标准 shader 或 splat 格式。

viewer 进程能启动不等于 inference 已完成视觉验证。3D/4D 方法的 release evidence
应先确认 geometry 与 camera data 有限，再在真实浏览器中打开实际产物，检查 canvas
非空且构图可读，执行 reset/orbit 或 timeline 交互，并检查 console error。官方
viewer 应作为小型 visualization plugin 保留；共享 Viser/Rerun scene layer 足够时，
不要复制其 inference runtime，也不要为单个模型另写 frontend。

## 启动矩阵

- **LingBot realtime** — `python -m worldfoundry.studio.ui.gradio_app lingbot-world --variant fast --frontend world --device cuda:1`. 常驻 runtime、持续 WebRTC 视频和 DataChannel 控制。
- **LingBot camera** — `python -m worldfoundry.studio.ui.gradio_app lingbot-world --variant base-camera --device cuda:1`. 更慢，偏 camera-centric profile。
- **MatrixGame** — `python -m worldfoundry.studio.ui.gradio_app matrix-game-2 --device cuda:1`. 交互式 world navigation。
- **WorldCam** — `python -m worldfoundry.studio.ui.gradio_app worldcam --device cuda:1`. Camera-path generation 和 view control。
- **Hosted APIs** — `python -m worldfoundry.studio.ui.gradio_app <model> --backend api_init --endpoint <url>`. Endpoint 在启动时显式固定。
- **Viser 点云** — `python -m worldfoundry.studio.ui.gradio_app pi3 --frontend points --asset /path/to/scene.ply --port 18590`. 原生 Viser UI。
- **Spark 3DGS** — `python -m worldfoundry.studio.ui.gradio_app vggt --frontend spark --asset /path/to/scene.splat --port 8765`. 独立 Spark canvas，不进入游戏机 shell。
- **Embodied simulator** — `python -m worldfoundry.studio.ui.gradio_app openvla --frontend embodied --simulator-url http://127.0.0.1:9000`. **计划中。** 仅登记外部 simulator URL，不会启动仓内 viewer。

```text
http://127.0.0.1:7868
```

## 交互模式

- **Image World** — 选择示例图或上传 image -> `START` -> 按住键盘或摇杆控制。image-conditioned 交互世界模型。
- **Video World** — 上传 video -> `START` -> 后续 video-to-video / continuation 流程。video-conditioned world model。
- **Stream** — seed input -> 启动一个持续会话 -> 按键边沿与生成帧连续流动。交互式世界模型和 continuation。
- **Prompt-scheduled segments** — 输入 prompt，可选一张 image，然后 `START`；当前 segment 完成后修改 prompt 并按 `Enter`。在原生 segment 边界接收新 prompt 的模型。
- **Queued controlled segments** — 选择初始 image、dense control video、sparse control video 和 prompt -> `RUN`；每次 `EXTEND` 前选择新的控制视频。每个 segment 都有显式控制输入的长时程模型。
- **Spatial preview** — 运行或导出 3D asset -> 打开 `3D World`。Gaussian splat、point cloud 或 scene outputs。

键盘/实时控制：

```text
WASD = move
Arrow keys / IJKL = look
```

键盘和摇杆的按下/释放边沿会立即通过当前实时通道发送。常驻 runtime 在模型
chunk 边界采样最新的有效控制状态；输入不会创建第二个 inference request，也
不会重新加载 pipeline。

### 实时文本事件、Idle step 与输出分辨率

`world` 前端在键盘和摇杆旁边提供三组有序控制：

- **文本事件：** 打开 **INITIAL SCENE**，选择 **ADD**，填入 event ID、按钮标签
  与 prompt。**APPLY** 会在会话开始前装载事件目录，或在会话进行中替换它。事件
  按钮会在下一个模型 chunk 边界激活一个文本条件；**CLEAR EVENT** 恢复基础
  prompt。没有状态保持式文本更新路径的模型会禁用这个入口，而不是假装接受了
  一次它无法应用的更新。
- **STEP：** 只排入一个不带键盘方向的生成 chunk，适合静止镜头或检查某个文本
  事件，不会开启自动生成循环。Queued-segment 模型的 **STEP** 保持禁用，因为
  它们的下一个 segment 需要新的控制视频。
- **OUTPUT：** 选择传输帧尺寸。**NATIVE** 保持模型输出尺寸；更小的选项只会对
  WebRTC/WebSocket 流做缩放和 letterbox，不会改变模型推理分辨率、采样步数、
  causal state 或后续世界质量。

Event ID 由 1–64 个字母、数字或 `_.:-` 组成；标签最长 64 字符，prompt 最长
1,000 字符，一个目录最多 12 个事件。目录更新带 revision，因此过期的编辑器
不会静默覆盖更新过的实时目录。

可靠控制通道会返回 `event_catalog_ack`、`event_ack`、`step_ack` 和
`output_config_ack`。事件或输出 ACK 表示这条有序请求已被接受，并说明它在哪里
生效（`next_chunk` 或 `next_segment`）；生成输出的完成信号仍然是 `chunk_done`。
分辨率切换固定在完整 transport chunk 的边界上，因此已经声明的 chunk 不会被
截断，也不会混用不同尺寸。每条请求与 ACK 携带相同的 `request_id`，所以快速
连点不会让旧响应覆盖当前 UI 状态。

不使用内置控件时，同一套协议也可以直接驱动：

```json
{"type":"event_catalog","request_id":"catalog-1","base_revision":0,"events":[{"event_id":"rain","label":"Rain","prompt":"Heavy rain begins.","category":"weather"}]}
{"type":"event","request_id":"event-1","event_id":"rain","state":"trigger"}
{"type":"event","request_id":"event-2","state":"clear"}
{"type":"action","request_id":"step-1","action":{"event":"step"}}
{"type":"output_config","request_id":"output-1","resolution":{"mode":"fixed","width":640,"height":360}}
```

固定传输尺寸必须是偶数，不小于 `160x90`，两个方向都不超过模型的原生/生成帧
尺寸，并且在实时 `1920x1080` 像素预算之内。Studio 只提供由 model catalog 推导
出的、对源安全的预设；原生尺寸未知时它不会猜测某个固定预设。切回
`{"mode":"native"}` 会移除传输层缩放。WebRTC 的缩放工作在帧进入 media track
之前完成，因此被保留的帧不会反复付出缩放代价，也不会阻塞控制事件循环。

### 可拖拽与可折叠面板

**STATUS**、**CONTROLS**、**INITIAL SCENE** 与 **RUNTIME** 共用同一套面板行为。
拖动面板标题栏可以让它浮在 viewport 上方，点 `−` 折叠，点 `+` 重新展开。
浏览器会把浮动面板限制在可见舞台内、把选中的面板置顶，并在本地保存位置与
折叠状态。拖动每个浏览器帧只做一次 animation-frame transform，不会给模型/帧
传输路径增加负担。在窄屏移动端布局中，面板保持在文档流内，但仍可折叠。

### 沉浸式全屏与实时运行日志

全屏视图属于共享的 `world` 前端，因此所有路由到该前端的交互模型都可以使用。
它会复用当前 peer 或 socket、帧缓冲和常驻模型会话。进入或退出全屏不会让
浏览器重连，也不会重启生成。

1. 按正常流程准备模型输入并启动会话。
2. 点击 viewport 左上角的 **FULLSCREEN**，或按 `F`。
3. 画面会铺满屏幕，并自动打开实时运行日志。
4. 点击 **LIVE LOG** 或按 `Shift+L`，可以在不退出全屏的情况下隐藏或显示日志。
5. 按 `Esc` 或点击 **EXIT**，返回标准 Studio 布局和同一个活动会话。

- **FULLSCREEN** / `F` — 进入或退出沉浸式全屏。
- **LIVE LOG** / `Shift+L` — 在普通布局或全屏布局中开关运行日志。单独按 `L` 仍然是视角向右控制。
- **CLEAR** — 只清空页面上可见的日志历史；不会重置模型会话或 runtime 状态。
- **`Esc`** — 退出全屏，回到同一个活动会话。

日志会展示 client/model 就绪状态、实时传输状态、segment 排队/生成/播放阶段、
错误和每个 chunk 的性能数据。chunk 完成后会记录帧数、生成耗时 (`gen`)、播放
队列深度 (`queue`) 和丢弃的旧帧数 (`dropped`)。这些内容用于当前交互会话排障；
它们不是持久化 run artifact，也不是服务端完整 stdout/stderr 的副本。

实时日志复用现有实时连接。浏览器按 animation frame 批量更新 DOM，并且最多
保留最近 120 条记录，因此长时间游玩不会无限扩大日志树，也不会在帧传输热路径
增加轮询。浏览器允许 Fullscreen API 时，点击按钮或使用快捷键会进入原生全屏；
如果原生全屏不可用或被浏览器策略阻止，Studio 会保持当前会话，并回退到铺满
浏览器视口的布局。
Workspace 的 visualizer iframe 已经授予 fullscreen 权限。

## 代码组织

Studio 的实现各自只有一个 canonical import path，根目录仅保留 CLI 与 worker 入口。

| 路径 | 职责 |
| --- | --- |
| `inference/catalog.py` | pipeline 发现、模型默认参数与 checkpoint 解析 |
| `inference/config.py` | 运行环境与分布式进程拓扑 |
| `inference/execution.py` | 输入准备、模型加载、执行与原始 artifact 保存 |
| `inference/dispatch.py` | GPU admission、受管子进程、resident worker、取消与 deadline |
| `inference/paths.py`、`inference/variants.py` | 运行路径和模型变体选择 |
| `serving/workspace.py`、`serving/jobs.py` | Workspace API 与 UI 任务调度 |
| `serving/` | 认证、文件服务、遥测和 realtime transport |
| `ui/` | Gradio 构建、浏览器启动选项、输入组件与模型展示 |
| `ui/workspace.html`、`ui/workspace.py` | 打包的 Workspace 页面和资源加载器 |
| `visualization/` | artifact 发现、viewer 路由与 geometry 展示 |
| `cli.py`、`runtime_job.py`、`workspace_job.py` | 安装命令与子进程入口 |

推理模块不导入 UI、serving 或 visualization。`StudioManager` 默认保存原始 artifact；需要预览的前端显式安装 `visualization.studio.prepare_run_record` 为 `record_processor`。原 `studio/native` 的 CUDA/C++/ImGui 前端已删除。

`visualization/plugins` 保留实际调用的实现：`perception/render.py` 用于 CLI 和 Grounding DINO；`perception/human_pose.py` 生成 Wan Animate conditioning；`scene3d/projection.py` 服务 VIPE；`scene3d/depth_anything_v3/export_vis.py` 服务 DA3 导出；`styles/colormaps.py` 提供 depth / normal 着色。未使用的 media、robotics、pixelSplat training 可视化、重复 DVLT、HED 和 sky-segmentation/GLB 链已删除。

`worldfoundry/representations` 仍是模型 adapter 包。VGGT、Pi3、WorldFM、Lyra 等 pipeline 直接使用其实现，因此保留；无实现和调用的 pixelSplat / Splatt3R marker class 已删除。

### 推理生命周期

受管 CUDA 推理在启动前获取设备租约。显式设备选择和 one-shot fallback 使用同一 admission 策略，resident worker 在所属进程组停止前持续持有租约。Linux 文件锁协调同一主机上的 WorldFoundry 控制器；`WORLDFOUNDRY_GPU_LEASE_DIR` 指定共享锁目录，默认 `/tmp/worldfoundry-gpu-leases-<uid>`。共享 GPU 的控制器应使用相同目录和物理设备标识；未受管 workload 不在此协调范围内。

`WORLDFOUNDRY_STUDIO_INFERENCE_TIMEOUT` 为 GPU 排队、worker 分配、请求排队、执行和输出 draining 提供一个 deadline，默认继承 resident timeout（未设置时六小时），`0` 关闭。取消和失败先清理所属进程组，再释放租约。主动创建其他 session 的进程不在进程组所有权约定内；托管 API 使用 provider 的 timeout / cancellation。

权重 pipeline 可缓存；API client 按请求创建，避免保留其他请求的凭据。持久命令任务使用独立 supervisor 和原子 completion receipt，控制器退出后仍能恢复真实状态。恢复后的进程必须通过 boot、start、session 和 group 身份核对才能接受信号，终态任务清理同时删除其 receipt。

默认 `python -m pytest` 运行公开 CPU 门禁；UI 和 renderer 回归位于 `tests/studio` 与 `tests/studio_visualization`，需要相应依赖。默认门禁不使用真实权重或 API 凭据。
