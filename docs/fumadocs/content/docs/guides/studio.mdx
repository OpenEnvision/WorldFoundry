## Introduction

WorldFoundry Studio is a thin visual entrypoint around repo pipelines. The model is fixed at launch time; use a new process for a different model family.

Studio exposes multiple frontends:

- **`world`** — Interactive world models. Standalone WebRTC console with a resident model runtime, reliable input-edge DataChannel, bounded in-memory frame queue, one persistent video track, immersive fullscreen, and a live runtime log. Decoded frames stream in memory without materializing an MP4 per control step.
- **`points`** — Viser point clouds / meshes. Starts native Viser directly instead of embedding it in the console shell.
- **`embodied`** — Embodied simulators. **Planned.** URL bridge only: Studio registers an external simulator URL and tunnel hints; no in-tree embodied viewer yet.
- **`spark`** — 3DGS. Starts the standalone Spark 3DGS viewer with repository-local Spark assets.
- **`media`** — Video, image, and audio artifact preview.
- **`rerun`** — Rerun recordings and timeline inspection.
- **`auto`** — Default. Routes interactive worlds to `world`, 3D scenes to `spark`, point/depth workflows to `points`, and embodied policies to `embodied`.

Before opening the Spark viewer, install its version-pinned browser modules:

```bash
python -m worldfoundry.studio.visualization.vendor_assets
python -m worldfoundry.studio.visualization.vendor_assets --check
```

The installer downloads missing, empty, or unreadable files and reuses readable
nonempty local modules. Install modules separately from starting Studio;
`--check` runs offline.

## What it shows

- **World console** — Live video, keyboard and joystick controls, immersive fullscreen, and runtime logs.
- **Geometry viewers** — Gaussian splats in Spark; point clouds and meshes in Viser.
- **Workspace** — Job status, preview media, artifact downloads, and viewer launch controls.

## Workspace mode

For multi-model work, run the workspace app instead of a single-model Studio process:

```bash
source tmp/worldfoundry_unified_env.sh
conda activate "${WORLDFOUNDRY_UNIFIED_ENV_PREFIX}"
```

```bash
bash scripts/workspace/run_workspace.sh \
  --host 127.0.0.1 \
  --port 7870 \
  --max-jobs 8
```

Use explicit roots when your checkpoints or benchmark data live outside the
default cache:

```bash
bash scripts/workspace/run_workspace.sh \
  --ckpt-dir /path/to/checkpoints \
  --data-dir /path/to/benchmark-data
```

The launcher resolves assets in this order: command-line option, already exported
environment variable, repo-sibling `ckpt/` or `data/` directory when present,
env-file value from `tmp/worldfoundry_unified_env.sh`, then
`~/.cache/worldfoundry/...`.

First-time CUDA setup is `bash scripts/setup/bootstrap_worldfoundry.sh`, the same official first-clone script as the [Quickstart](/docs/quickstart). Start the Workspace from that unified model runtime, not from a
lightweight UI-only environment. For CUDA 12.8 hosts this is usually
`worldfoundry-unified-cu128` after `source tmp/worldfoundry_unified_env.sh`. If
**LOAD** or **START** fails with a missing import such as `cv2`, restart `7870`
from that unified environment before debugging model code.

Do not copy or relocate a prepared conda environment between machines. Native
Python and OpenSSL links can point back to the original prefix, which makes
resident inference workers fail even when the browser server starts. If the
Workspace reports a missing `python3.x`, missing `cv2`, or `libssl`/`libcrypto`
error, recreate or verify the unified env through the public setup command:

```bash
bash scripts/setup/bootstrap_worldfoundry.sh --verify-only
source tmp/worldfoundry_unified_env.sh
bash scripts/workspace/run_workspace.sh
```

Open:

```text
http://127.0.0.1:7870/
```

Use the workspace to submit inference jobs, inspect model-specific forms, review artifacts,
and compare runs without switching between multiple one-off scripts.
Those Workspace jobs are visual smoke (`python -m worldfoundry.studio.workspace_job infer`). Everyday reproducible / model-page commands use `wf run <id> --pipeline.task-profile …`. See [CLI entrypoints](/docs/reference/cli#entrypoints).

Workspace also supports evaluation jobs. For VBench, select **Evaluation**,
choose benchmark `vbench`, put generated videos in **Dataset Root** (or an
official VBench results JSON in **Results Path**), and set **Metrics** to one or
more dimensions such as `aesthetic_quality`, `motion_smoothness`, or the preset
`custom_supported`. VBench-specific runtime options such as
`{"mode":"custom_input","load_ckpt_from_local":true}` go in **Eval Runtime
JSON**.

### Create Job configuration

There is no separate **Settings** page in the Workspace UI. Configure each job
in the **Create Job** dialog before submission.

- **Model / variant / task profile** — Which catalog entry runs and which official input contract is exposed.
- **Prompt, input path, dynamic task fields** — Model-specific inputs from the inference contract.
- **Device, backend, attention** — Runtime device and loading path (`auto`, `from_pretrained`, `api_init`).
- **Frames, FPS, height, width, steps, guidance, seed** — Generation parameters sent in the job payload.
- **Runtime checks** — Optional memory/compile toggles such as Torch Compile, CPU Offload, VAE Offload, and Text Encoder Offload. These appear only when the selected model advertises support.
- **Call JSON / Load JSON** — Advanced overrides merged into `call_kwargs` and `load_kwargs`.

The attention selection follows the model's declared loading and inference
boundaries. A load-only option is not copied into inference kwargs. Explicit
Load JSON and Call JSON values take precedence at their respective supported
boundary; unsupported explicit kwargs remain validation errors.

When you open **Create Job** or switch task profiles, the form is prefilled from
Workspace defaults loaded at startup. Model-specific official demo values from
the catalog and task profile still take precedence over those shared defaults.

### Optional persisted defaults

To reuse the same defaults across Workspace restarts, point the server at a
JSON settings file:

```bash
export WORLDFOUNDRY_STUDIO_SETTINGS_FILE=/path/to/studio-settings.json
```

On startup, the Workspace loads that file into `/api/settings`. The Create Job
form reads those values through `GET /api/settings`. Operators can also update
the file programmatically with `POST /api/settings`:

```bash
curl -sS -X POST http://127.0.0.1:7870/api/settings \
  -H 'Content-Type: application/json' \
  -d '{"values":{"fps":12,"num_frames":49,"attention_backend":"torch"}}'
```

When `WORLDFOUNDRY_STUDIO_SETTINGS_FILE` is unset, defaults live only in the
running Workspace process and reset on restart.

### Optional NVIDIA RTX post-processing

RTX Video Super Resolution is outside the model's causal state: it transforms
decoded RGB frames immediately before transport and preserves frame count,
ordering, dtype, and numeric range. Studio advertises the postprocessed size as
the transport's **Native** resolution and derives smaller transport choices
from it. The package is intentionally absent from
the default and `all` extras because `nvidia-vfx` uses NVIDIA's proprietary
license. Install and select it explicitly:

```bash
pip install 'worldfoundry[studio_realtime,rtx_postprocess]'

export WORLDFOUNDRY_REALTIME_POSTPROCESS_PRESET=rtx-super-resolution
export WORLDFOUNDRY_REALTIME_RTX_SCALE=1.5
python -m worldfoundry.studio.cli <model-id> --frontend world --device cuda:0
```

The adapter validates the installed package, CUDA visibility, device index,
Turing-or-newer compute capability, and the Linux NGX driver library before the
server starts. It then loads the selected native effect and processes one
representative frame, so an incomplete driver image fails before Studio begins
serving. The backend receives contiguous CHW `float32` CUDA frames in `[0, 1]`,
and its borrowed DLPack output is cloned before the next effect call. Inspect
static prerequisites or run the full native probe without starting Studio:

```bash
python -c 'from worldfoundry.core.media.processing.rtx import inspect_rtx_vfx_capability as check; print(check(device=0).to_payload())'
python -c 'from worldfoundry.core.media.processing.rtx import probe_rtx_vfx_runtime as probe; print(probe(device=0).to_payload())'
```

On Linux, `VideoSuperRes` also needs `libnvidia-ngx.so.1`. Compute-only or
headless driver images can omit it even when CUDA and `nvidia-smi` work. Install
the NGX/OpenGL userspace component from the **exact same driver release**
(commonly `libnvidia-gl-<driver-major>`) and make it visible to the dynamic
linker before Python starts; do not mix driver-library versions.

Supported OS and driver versions are controlled by NVIDIA; check the current
[NVIDIA VFX Python requirements](https://pypi.org/project/nvidia-vfx/) before
deployment. VSR increases transport pixels and adds work to `postprocess_ms`,
so capture an A/B trace and keep the regression gate below. For low-latency
control, start at 1.5x `HIGH`; reserve `ULTRA` and 2–4x output for GPUs with
measured headroom. `rtx-deblur-ultra` is same-resolution and therefore avoids
the bandwidth increase.

`WORLDFOUNDRY_REALTIME_POSTPROCESS_PRESET` names an entry in the post-processing
preset registry (`worldfoundry.core.media.processing.presets`); one preset runs
per Studio process. Studio builds the selected processor and runs its probe
before serving, and `WORLDFOUNDRY_REALTIME_RTX_*` overrides are rejected unless
an RTX preset is selected.

### Browser presentation timing and encoder feedback

The WebRTC status strip shows **E2E**, the median time from submitting a control
in the browser to presenting a frame from the chunk that consumed it. Hover over
the strip for p90, server control-to-queue time, RTT, jitter-buffer delay, and
decode time. The distribution contains the latest 256 measured controls and
excludes configured warmup chunks. Keyboard/joystick edges, mouse deltas,
physical and virtual stick levels, STEP, and live text updates carry control IDs.
Axis IDs follow the resampler: delta messages contribute to their sampled chunk;
level messages overwritten within one input frame are excluded. Held nonzero
levels retain their IDs across chunks, but neutral samples are not attributed to
later idle frames. STEP does not consume queued axis IDs. Controls without a
matching presented frame do not create latency samples.

Frame receipts carry the actual RTP timestamp, chunk index, and frame index over
the existing DataChannel. The browser matches them to
`requestVideoFrameCallback().rtpTimestamp`, including when video arrives before
its receipt. Repeated hold frames count once per control. Both endpoints keep
bounded, session-local timing histories. Browser duration measurements never
subtract a server clock from a browser clock.

With `WORLDFOUNDRY_REALTIME_PERF_JSONL` set, the trace also records
`realtime.frame_presented` (control ID, chunk/frame identity, `control_to_display_ms`,
`queue_ms`, and `encode_ms`) and `realtime.browser_transport` (two-second WebRTC
stats samples). These are separate from `realtime.chunk_timing`; the chunk
regression manifest below continues to evaluate server-side generation. Browser
stats use interval deltas for bitrate, average jitter-buffer delay, and decode
time. Timing receipts yield to controls when the DataChannel is congested.

The existing opt-in NVENC path (`WORLDFOUNDRY_REALTIME_NVENC=1`) forwards receiver
PLI/FIR requests to the next native encode and REMB bandwidth estimates to the
encoder's CBR configuration. Reconfiguration runs on the encoder worker, keeps
the RTP clock, and retains CUDA-backed pixels. The target is bounded by the
configured/resolution-derived bitrate ceiling and a 100 kbit/s floor (or a lower
explicit ceiling). Reductions apply at the next encode; increases below 10% are
coalesced. Model cadence, inference resolution, and frame queue policies are
unchanged.

**Limitations:** E2E measures a correlated chunk frame reaching the browser's
presentation callback, not a detected pixel response or physical display scanout.
Browsers without RTP timestamps in video-frame callbacks, WebSocket playback,
or sessions without matching receipts show E2E as unavailable rather than
substituting server time. NVENC feedback requires PyNvVideoCodec and a GPU with an NVENC engine;
CUDA availability alone is insufficient. Encoder bitrate adaptation changes
transport compression quality, not generated model pixels.

### Weight-free browser UI checks

`tests/manual/realtime_browser_ui.mjs` opens an isolated Chromium window with a
temporary profile and serves the production HTML, CSS and JavaScript on loopback.
It checks model-declared keys, virtual stick axes and key fallback, Pointer Lock
and mouse movement, stick rest and focus-loss handling, continuous progress,
pause/resume, STEP rejection, prompt restart and reset. HTTP/WebSocket model
responses and gamepad readings are fixtures.

Use a desktop session, the Studio Python environment, Node.js, and Playwright 1.65:

```bash
npm install --prefix /private/replay-browser playwright@1.65.0
/private/replay-browser/node_modules/.bin/playwright install chromium
NODE_PATH=/private/replay-browser/node_modules PYTHON=python \
  node tests/manual/realtime_browser_ui.mjs outputs/realtime-browser-ui
```

The output directory must be new. `CHROMIUM_EXECUTABLE` can select an existing
Chromium binary. Keep the test window in the foreground while the runner exercises
its tabs. `browser.json`, `chromium.log` and screenshots retain the results; the
temporary browser profile is removed when the runner exits.

For an operator-assisted physical Escape check, run a separate session:

```bash
NODE_PATH=/private/replay-browser/node_modules PYTHON=python \
  node tests/manual/realtime_browser_ui.mjs outputs/realtime-physical-escape --physical-escape
```

Click the video in the test window, press the keyboard's **Esc** key, and keep the
window focused until the check finishes. The runner waits up to ten minutes. It
records native pointer release while focused and verifies that subsequent mouse
movement sends no axes; switching away from the window does not pass the check.

**Evidence scope:** real DOM, keyboard, mouse, tab focus and browser Pointer Lock
APIs with substituted model responses. The automatic suite releases the pointer
through `exitPointerLock()`; the separate `--physical-escape` mode requires an
operator. Gamepad readings remain simulated. Neither mode is checkpoint,
WebRTC transport or inference-performance evidence.

### Checkpoint-backed network replay

`tests/manual/realtime_replay.py` launches the public Studio CLI with local
weights and drives the actual Chromium client. Each repeat resets the session,
reuses a fixed seed and image, and issues one STEP per native model chunk. It
waits for that chunk's final source frame to be presented before issuing the next
STEP. The example uses Matrix-Game 2's native 640×352, 12 FPS, 9/12-frame cadence,
three repeats per network condition, one warmup chunk and six measured chunks.

Prepare the unified Python environment, Node.js and Playwright/Chromium with its
system libraries. Browser packages can live outside the checkout:

```bash
npm install --prefix /private/replay-browser playwright
/private/replay-browser/node_modules/.bin/playwright install chromium
export NODE_PATH=/private/replay-browser/node_modules
cp tests/manual/realtime_replay.example.json /private/realtime-profile.json
# Edit model_ref, image and the physical GPU index in the private profile.
source tmp/worldfoundry_unified_env.sh
PYTHONPATH=. "$WORLDFOUNDRY_UNIFIED_ENV_PREFIX/bin/python" \
  tests/manual/realtime_replay.py \
  --profile /private/realtime-profile.json \
  --output outputs/realtime-mg2-run
```

The output directory must be new. `CHROMIUM_EXECUTABLE` can select an existing
Chromium binary. All browser/server processes run on the same Linux host; the
runner binds Studio and its UDP relay to loopback. No root access or changes to
host network interfaces are needed.

The clean, limited/lossy and interrupted-link cases all use the same isolated
UDP relay. Both SDP candidate sets are rewritten, and the selected remote ICE
candidate must point to the relay. Delay, jitter, serialization rate and seeded
packet loss therefore affect WebRTC media, feedback and DataChannel traffic,
not just HTTP signaling. `delay_ms` is per direction; `rate_bps: 0` means
unlimited. The finite `queue_ms` budget drops excess queued datagrams. The
interruption case drops both directions for 1.5 seconds during measured STEP
requests. Link counters record loss, queue and interruption drops separately.

Artifacts include `report.json`, `report.md`, raw `timing.jsonl`, `browser.json`,
per-run screenshots, one-second Studio process CPU/RSS/GPU-memory samples, and
`environment.json` with source state, package versions, command and GPU
co-tenancy. The report retains each repeat's E2E p50/p90, missing controls,
unique generated frames presented, presentation gaps and WebRTC stats. CPU
percent is for the Studio process, with 100% equal to one CPU core. GPU memory
is a sampled process footprint, not the CUDA allocator's exact peak.

Missing runs, unmatched browser/server receipts, browser errors, incomplete
chunks or failed reset/shutdown checks fail the run. Server-side thresholds
reuse `RealtimeRegressionThresholds`; the private profile can additionally set
`max_e2e_p90_ms`, `max_stall_fraction` and `max_reset_ms` under
`delivery_thresholds`. Set latency limits from an accepted, matched-stack
baseline; the example checks completeness and lifecycle without inventing a
latency target. Preserve the profile and all per-run values for comparisons.

**Evidence scope:** This is checkpoint-backed transport and lifecycle evidence,
not the accepted numerical replay required for inference changes. Presentation
gaps can include generation and intentional pacing. Shared-GPU measurements
must retain their co-tenancy context. The default profile uses software encoding;
negotiated H.264 alone does not certify NVENC execution.

Weight-free script and report contracts run in `make test-infer-tensors` and
`make test-realtime-client`; the checkpoint/browser replay remains manual.

### Coordinate-system contract

Viewer launch is part of the geometry contract. A valid artifact can still look
upside down or tilted when its world frame is interpreted twice. Keep points,
meshes, camera-to-world transforms, frustums, and trajectories in one declared
frame:

- An official GLB that already applies OpenCV-to-OpenGL alignment must use
  `coordinate_preset=asset-native` and the exporter-defined up axis. VGGT and
  VGGT-Omega official GLBs use `+Y` up and `alignment=none`.
- A raw VGGT/VGGT-Omega prediction NPZ remains in the model's OpenCV frame, so
  Viser applies `coordinate_preset=opencv-to-opengl` once and uses `+Y` up.
- Raw UniDepth V2 model-point NPZ files also use the OpenCV camera frame. Its
  Workspace PLY exporter instead persists `x-right/y-up/z-forward`, so those PLY
  files use `asset-native`, `+Y` up, and `alignment=none` without a
  second flip.
- LoGeR and Pi3 PLY point clouds keep their predicted camera-to-world
  sidecars. Viser applies `first-camera-opengl` to points and cameras together,
  uses `+Y` up, and frames the central 5-95% geometry range so sparse outliers do
  not shrink the useful scene.
- Rerun recordings must log the world `ViewCoordinates` and use the same camera
  convention in every `Pinhole`. Cut3R uses RDF for both world and camera
  entities.
- Never fix an orientation mismatch by flipping only the point cloud. Apply the
  same rigid transform to geometry and camera-to-world poses, then verify reset,
  orbit, and timeline interaction in a browser.

Workspace resolves the proven VGGT, LoGeR, and Pi3 defaults automatically.
The Visualizer defaults also cover UniDepth V2 raw/Workspace assets.
The Visualizer Params JSON remains an explicit override for other exporters. Viser reports the
actual bound port when its requested port is occupied. Rerun uses WebGPU
by default; set `WORLDFOUNDRY_STUDIO_RERUN_RENDERER=webgl` only when the target
browser requires that fallback.

### Choosing a 3D viewer

Keep the default route artifact-driven so model integrations do not duplicate
viewer code:

- **Static point cloud, mesh, depth-derived geometry, camera frustums** — Default Viser. Use the official viewer when it carries a model-specific control or annotation that cannot be represented as shared scene layers.
- **Time-varying geometry, camera trajectory, synchronized images/depth/actions** — Default Rerun. Use the official viewer when the official timeline cannot be exported to `.rrd` without losing semantics.
- **Gaussian splats** — Default Spark. Use the official viewer when the upstream renderer requires a nonstandard shader or splat format.

An inference run is not visually verified merely because a viewer process
starts. To verify a 3D/4D method, confirm finite geometry,
camera data, and the declared coordinate frame, then open the actual artifact in a browser, check a nonblank and
readably framed canvas, exercise reset/orbit or timeline controls, and review
console errors. Preserve an official viewer as a small visualization plugin;
do not copy its inference runtime or build a per-model frontend when shared
Viser/Rerun scene layers are sufficient.

## Interaction modes

- **Image World** — Select a tray image or upload an image -> `START` -> hold keyboard or stick controls. Image-conditioned interactive world models.
- **Video World** — Upload a video -> `START` -> continue with video-to-video world-model flows. Video-conditioned world models.
- **Stream** — Seed input -> start one persistent session -> send key edges while frames continue. Interactive world models and continuation.
- **Prompt-scheduled segments** — Enter a prompt, optionally select an image, then `START`; edit the prompt and press `Enter` after the current segment. Models that accept a new prompt at native segment boundaries.
- **Queued controlled segments** — Select an initial image, dense control video, sparse control video, and prompt -> `RUN`; select new controls before each `EXTEND`. Long-form models with explicit per-segment control inputs.
- **Spatial preview** — Run or export a 3D asset -> open Spark for Gaussian splats or Viser for point clouds and meshes through Workspace Visualizers.

Keyboard/live controls:

```text
WASD = move
Arrow keys / IJKL = look
```

Keyboard and stick edges are sent immediately over the current realtime channel.
The resident runtime resamples queued transitions into each model chunk without
creating another inference request or reloading the pipeline. A short tap remains
pending until its active state spans at least one input-frame sampling interval,
even if it was released during generation. Sampling may extend a sub-frame tap;
observing current held keys does not consume queued transitions. The worker stays
awake until pending input is drained, then resumes its normal idle behavior.

Models can declare their own key bindings in `RealtimeSpec.keys`. The page then
accepts exactly those keys and lists them in the control legend. A virtual stick
is hidden only when the model declares neither its keys nor its axes. Omitting
`keys` keeps W/A/S/D and I/J/K/L; `keys: []` disables key input. Prompt-scheduled
and queued-segment pages take no keyboard actions.

#### Mouse, gamepad, and virtual sticks

Models that declare `RealtimeSpec.axes` also accept mouse or stick input. The
control legend names the inputs the model accepts:

- **Mouse** (`mouse_x`/`mouse_y` axes): once the session is live, a hint asks
  you to click the video. The click captures the pointer, and mouse motion is
  summed and sent at most once per animation frame. `Esc` releases the pointer
  and stops sending.
- **Gamepad** (`gamepad_*` axes): Studio reads the first connected gamepad every
  animation frame and sends the four stick levels when a component changes by
  more than 0.02 or returns to zero. Browsers expose gamepads only on a secure
  origin (HTTPS or `localhost`) and after a button press, so the legend lists
  **GAMEPAD** once a gamepad is reported.
- **Virtual sticks:** the existing movement and camera sticks map to
  `gamepad_lx`/`gamepad_ly` and `gamepad_rx`/`gamepad_ry`. Each declared direction
  sends a continuous value in `[-1, 1]`; directions without an axis retain their
  declared-key mapping. The model's deadzone, scale and limit still apply on the
  server. A captured drag takes priority over the physical stick for its declared
  directions. Releasing it restores the physical stick's current values, or zero
  when no gamepad is connected. Virtual axes also work without the Gamepad API.

Window blur or a hidden tab clears virtual drags and sends neutral levels. An old
pointer cannot reactivate the drag when focus returns. Physical stick input
resumes on focus return; disconnecting a gamepad resamples the remaining inputs
without clearing an active virtual drag.

Over WebRTC, mouse deltas use the unordered `axes` DataChannel. Physical and
virtual stick levels use the reliable `controls` channel, because the server holds each level until
the next sample and a lost return-to-rest sample would keep the stick held.
While a channel is congested, samples wait for a later frame and mouse motion
keeps accumulating. The WebSocket transport sends the same messages on its
socket.

#### Input sampling limits

Input retention guarantees a control sample, not immediate visible motion in the
same generated chunk. MatrixGame2's stride-4 action encoder may consume the final
input row in a later chunk. A final-row-only action still needs that subsequent
chunk; input retention alone does not drain the model's action history.

### Live text events, idle steps, and output resolution

The `world` frontend exposes three ordered controls beside the keyboard and
joysticks:

- **Text events:** open **INITIAL SCENE**, choose **ADD**, and enter an event ID,
  button label, and prompt. **APPLY** installs the catalog before a session or
  replaces it while the session is live. Event buttons activate one text
  condition at the next model chunk boundary; **CLEAR EVENT** restores the base
  prompt. Models without a state-preserving text-update path disable this
  surface instead of acknowledging an update they cannot apply.
- **STEP:** queues exactly one generated chunk without keyboard or axis input;
  it does not reuse the previous chunk's controls. It is useful for an idle camera
  or for checking a text event. It does not enable an autonomous generation loop.
  Queued-segment models keep **STEP** disabled
  because their next segment requires new control videos.
- **OUTPUT:** selects the transmitted frame size. **NATIVE** preserves the model
  output size. Smaller choices resize and letterbox only the WebRTC/WebSocket
  stream; they do not change model inference resolution, sampling steps, causal
  state, or future world quality.

Event IDs contain 1-64 letters, numbers, or `_.:-`; labels are at most 64
characters, prompts are at most 1,000 characters, and a catalog contains at most
12 events. Catalog updates carry a revision so a stale editor cannot silently
overwrite a newer live catalog.

The reliable control channel returns `event_catalog_ack`, `event_ack`,
`step_ack`, and `output_config_ack`. An event or output ACK means the ordered
request was accepted and reports where it takes effect (`next_chunk` or
`next_segment`); `chunk_done` remains the completion signal for generated
output. Resolution changes are frozen at a complete transport-chunk boundary,
so an already announced chunk is never truncated or mixed across dimensions.
Each request and ACK carries the same `request_id`, so rapid clicks cannot let
an older response overwrite the current UI state.

The same protocol can be driven without the built-in controls:

```json
{"type":"event_catalog","request_id":"catalog-1","base_revision":0,"events":[{"event_id":"rain","label":"Rain","prompt":"Heavy rain begins.","category":"weather"}]}
{"type":"event","request_id":"event-1","event_id":"rain","state":"trigger"}
{"type":"event","request_id":"event-2","state":"clear"}
{"type":"action","request_id":"step-1","action":{"event":"step"}}
{"type":"output_config","request_id":"output-1","resolution":{"mode":"fixed","width":640,"height":360}}
```

Fixed transport dimensions must be even, at least `160x90`, no larger than the
model's native/generated frame on either axis, and within the realtime
`1920x1080` pixel budget. Studio advertises only source-safe presets derived
from the model catalog; if the native size is unknown, it does not guess a
fixed preset. Switching back to `{"mode":"native"}` removes the transport
scaler. WebRTC resize work runs before frames enter the media track, so held
frames do not repeatedly pay the resize cost or block the control event loop.

### Continuous sessions

Models whose `RealtimeSpec.advance` is `continuous`, such as native
Self-Forcing, generate chunk after chunk on their own once the session starts.
For these sessions the page shows:

- rollout progress in the status strip, as `CHUNK 3/7`, or as a running count
  when the model sets no `max_chunks` limit;
- **PAUSE**/**RESUME** beside **STEP**, which stops and restarts auto-advance.
  **STEP** is enabled while the rollout is paused and generates one chunk;
- `ROLLOUT COMPLETE` once the rollout reaches `max_chunks`. **STEP** on a
  finished rollout shows the server's reason next to the controls.

A new prompt, submitted with `Enter` at any time, starts a new rollout and
restarts the chunk count. Sessions that generate only on input keep the
controls described above.

### Draggable and collapsible panels

**STATUS**, **CONTROLS**, **INITIAL SCENE**, and **RUNTIME** share the same panel
behavior. Drag a panel header to float it above the viewport, click `−` to
collapse it, and click `+` to reopen it. The browser clamps floating panels to
the visible stage, raises the selected panel, and saves positions and collapsed
state locally. Dragging uses one animation-frame transform per browser frame and
does not add work to the model/frame transport path. On narrow mobile layouts,
panels stay in document flow but remain collapsible.

### Immersive fullscreen and live runtime log

The fullscreen view is part of the shared `world` frontend and is available to
every interactive model routed to that frontend. It reuses the current peer or
socket, frame buffer, and resident model session. Entering or leaving fullscreen
does not reconnect the browser or restart generation.

1. Prepare the model input and start the session normally.
2. Click **FULLSCREEN** in the upper-left corner of the viewport, or press `F`.
3. The viewport fills the screen and the live runtime log opens automatically.
4. Click **LIVE LOG** or press `Shift+L` to hide or show the log without leaving
   fullscreen.
5. Press `Esc` or click **EXIT** to return to the standard Studio layout.

- **FULLSCREEN** / `F` — Enter or leave immersive fullscreen.
- **LIVE LOG** / `Shift+L` — Toggle the runtime log in either the normal or fullscreen layout. `L` alone remains the camera-right control.
- **CLEAR** — Clear the visible log history only; the model session and runtime state are unchanged.
- **`Esc`** — Leave fullscreen and return to the same active session.

The log includes client and model readiness, realtime transport state, segment
queue/generation/playback transitions, errors, and per-chunk performance data.
A completed chunk reports its frame count, generation time (`gen`), playback
queue depth (`queue`), and discarded stale frames (`dropped`). These entries are
session telemetry for interactive debugging; they are not persisted run
artifacts or a copy of the server's complete stdout/stderr stream.

Live log events use the existing realtime connection. The browser batches DOM
updates on animation frames and retains at most the latest 120 entries, so a
long session does not accumulate an unbounded log tree or add a polling loop to
the frame path. When the browser permits the Fullscreen API, the button or
keyboard shortcut enters native fullscreen. If native fullscreen is unavailable
or blocked by browser policy, Studio keeps the same session and falls back to a
viewport-filling layout. The Workspace visualizer iframe already grants
fullscreen permission.

## Code layout

Each implementation has one canonical import path. There are no forwarding
modules at the Studio root.

| Location | Responsibility |
| --- | --- |
| `inference/catalog/` | Model catalog: `discovery.py` (AST pipeline scan, entry building, `find_entry`), `models/<family>.py` (curated overrides and per-model defaults), `resolve.py` (checkpoint and path resolution), `params.py` (shared parameter templates). |
| `inference/config.py` | Runtime environment and distributed process topology. |
| `inference/execution.py` | Prepare inputs, load pipelines, execute, and persist raw run artifacts. |
| `inference/dispatch.py` | GPU admission, managed subprocesses, resident workers, cancellation, and deadlines. |
| `inference/paths.py`, `inference/variants.py` | Runtime paths and model variant selection. |
| `inference/listing.py` | Studio-visible catalog listing shared by the Workspace, launcher, and TUI. |
| `serving/` | Authentication, file serving, telemetry, and realtime transport. |
| `visualization/` | Artifact routing (`registry.py`, `artifacts.py`, `run_record.py`), preview conversion (`presentation.py`), and browser backends. |
| `visualization/launcher.py`, `visualization/launch_config.py` | Standalone frontend routing and browser launch options. |
| `visualization/interfaces.py`, `visualization/vendor_assets.py` | Model interface specs and pinned browser modules. |
| `workspace/app.py`, `workspace/jobs.py` | Workspace API and in-process UI job scheduling. |
| `assets/web/` | Packaged Workspace page and the world frontend CSS/JS. |
| `cli.py` | Installed `wf-studio` command. |
| `runtime_job.py` | Subprocess and resident inference worker entrypoint. |
| `workspace_job.py` | CLI adapter for Workspace inference requests. |

The inference modules do not import the frontend, serving, or visualization
packages. `StudioManager` saves raw artifacts by default. Frontends explicitly
install `visualization.presentation.prepare_run_record` as the `record_processor`
when they need preview conversion.

The standalone browser backends run through `wf-studio`.

Wan Animate conditioning images are model inputs, owned by
`base_models/diffusion_model/models/encoders/wan/variants/animate/render.py`

Geometry providers discover actual artifacts; a directory of Python source is not a renderable scene.

import their runtime from the corresponding family in
`worldfoundry/base_models/three_dimensions`. Checkpoint loading, preprocessing
and geometry postprocessing live beside the model code. Studio visualization
owns artifact display.

### Inference lifecycle

Managed CUDA runs acquire a device lease before launching. Explicit device
selection and fallback to one-shot workers use the same admission policy.
Resident workers retain their lease until their owned process group stops.
On Linux, file locks coordinate cooperating WorldFoundry controllers on the
same host; `WORLDFOUNDRY_GPU_LEASE_DIR` selects the shared lock directory
(default: `/tmp/worldfoundry-gpu-leases-<uid>`). Controllers sharing GPUs must
use the same directory and device identities. Unmanaged workloads are outside
this admission policy.

`WORLDFOUNDRY_STUDIO_INFERENCE_TIMEOUT` is one deadline for GPU queueing,
worker allocation, request queueing, execution, and output draining. It defaults
to the resident timeout setting (six hours when unset); `0` disables it.
Cancellation and failure stop the owned process group before releasing its
lease. A process that deliberately creates a different session is outside
this process-group ownership contract. Hosted API calls use their provider's
timeout and cancellation mechanisms.

Weight pipelines can be cached. API clients are request-scoped so a reused
pipeline cannot retain another request's credentials.

Persistent command jobs use a separate supervisor and atomic completion
receipts to recover their real exit status after the controller exits.
Restored jobs require matching boot, process-start, session, and group identity
before signalling a saved PID. Retention removes completed receipts together
with terminal job metadata.

### Checks

`python -m pytest` runs the public CPU inference gate. Optional renderer and UI
regressions live in `tests/studio_visualization` and `tests/studio`; install
their dependencies before selecting those suites. No real weights or API
credentials are needed by the default gate.
