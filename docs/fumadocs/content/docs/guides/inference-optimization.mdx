<Callout type="warn" title="Experimental">
These optimizations are experimental. They may change, may not apply to every model, and should not be treated as a supported production contract.
</Callout>

WorldFoundry only treats a technique as available when a public control exists and the main path consumes it. An accepted flag is not a speedup. After a forward, read `requested / effective / fallbacks` from `runtime_optimization_report()`.

[Pluggable diffusion acceleration](/docs/guides/diffusion-acceleration) covers the Sol-Engine / FlashDreams comparison, native SANA/Wan adapters, removal and request isolation, and configurations accepted or rejected by complete video diagnostics.

Most named knobs below are on the **native Wan 2.1 / Wan 2.2** pipelines (`Wan2p1*`, `Wan2p2*`, including VACE). Wan 2.5 / 2.6 / 2.7 are hosted APIs and have no local kernel controls. Other native recipes share only a subset (dtype, offload, sometimes attention or VAE tiling). Family runtimes (LTX, CogVideoX, and the rest) keep their own flags — do not copy Wan keys onto them.

<Callout type="info" title="Accepted is not effective">
Missing kernels, calibration, process groups, or checkpoint weights fail at build time or report an explicit dense / SDPA fallback. Wrapper installation alone (`*-wrapper-installed (runtime-pending)`) is not acceleration.
</Callout>

## Default recommendation

<Callout type="idea" title="First run vs throughput">
**First run / official-looking output.** Keep the catalog defaults: `torch_dtype="bfloat16"`, `offload_mode="resident"` when VRAM fits (Studio default for Wan2.2 TI2V-5B), otherwise `async-block`. Leave feature cache, approximate attention, quantization, CUDA Graph, and TAEW preview off. Do not cut steps or CFG for an official benchmark.

**Throughput on the same checkpoint.** Stay resident BF16. Set `attention_backend` to a real Flash / Sage provider for your GPU, then `fuse_qkv=True`, `fused_rope=True`, and `static_cross_kv=True`. Add `compile=True` only after a warmup request — the first compiled forward is slow. Turn on Wan VAE spatial tiling / temporal chunks if decode OOMs or dominates latency. Add **one** feature-cache algorithm only if you accept skipped DiT steps.
</Callout>

## What you can do

These controls are wired. Enable them from `from_pretrained(...)`, Workspace **load JSON**, or `worldfoundry-eval run --pipeline.load.<kebab-name>` when that key is on the model’s load schema.

### Distilled checkpoints

Wan2.2 public pipelines accept `peft_adapter_path` and merge a PEFT LoRA after an adapter/base/target audit. Quality and step count belong to that distilled checkpoint. There is no separate “4-step mode” without matching weights.

### Preview decode only

`vae_preview_decoder_path` swaps the Wan2.2 48-channel official VAE for TAEW2.2. That is a fast, approximate, decode-only preview. Official VAE tiling, temporal chunking, and VAE-parallel do not apply because the official decoder is not built. Do not use TAEW for final-quality or official-benchmark videos.

## How to turn knobs on

The same load keys work from Python, CLI, or Workspace.

<Callout type="info" title="Nested objects stay off the CLI">
`feature_cache`, `approximate_attention`, and `quantization` belong in Python kwargs or load JSON — not a guessed CLI flag.
</Callout>

Complete surface for native Wan 2.1 / 2.2:

from worldfoundry.pipelines.wan.pipeline_wan_2p2 import Wan2p2Pipeline

pipe = Wan2p2Pipeline.from_pretrained(
    model_path="/checkpoints/Wan2.2-TI2V-5B",
    device="cuda",
    # Placement
    offload_mode="resident",
    torch_dtype="bfloat16",
    dit_weight_dtype="bf16",
    # Attention and exact kernels
    attention_backend="flash3",
    fuse_qkv=True,
    fused_rope=True,
    static_cross_kv=True,
    compile=False,
    # Lossy — enable at most one cache, and not with SP / CUDA Graph:
    # feature_cache={"algorithm": "teacache"},
    # Wan VAE decode
    vae_decode_autocast="bf16",
    vae_spatial_tiling=True,
    vae_tile_size=(34, 34),
    vae_tile_stride=(18, 16),
    vae_temporal_chunk_size=4,

## Trace stages without synchronizing CUDA

Set `WORLDFOUNDRY_NVTX=1` when recording an Nsight Systems trace. For example,
replace `inference.py` below with your existing inference script:

```bash
WORLDFOUNDRY_NVTX=1 nsys profile --trace=cuda,nvtx,osrt -o inference-trace python inference.py
```

The standard `NativeDiffusionRunner` emits `worldfoundry.run`, `encode`,
`denoise_step`, `denoiser.positive/negative`, and `decode` ranges. The shared
video postprocessor and H.264 writer emit `worldfoundry.postprocess` and
`worldfoundry.output.h264`; packed offload copies emit `worldfoundry.offload.h2d`.
Custom runners only inherit ranges for the shared methods they call.
Ranges label host submission and introduce no CUDA synchronization. They do
not measure client display latency. With the switch unset, ranges do not import
PyTorch or probe CUDA; with no CUDA available, they are a no-op.

## Reusable offload buffers and GQA compatibility

Opt in through the Python helper `enable_layerwise_cpu_offload(..., reuse_buffers=True)` to pack
contiguous weights by dtype into aligned CPU buffers and reuse at most two CUDA
slots. CUDA events prevent overwriting a slot while compute still reads it.
Its report includes `buffer_mode` and `device_buffer_bytes`. Non-contiguous
weights preserve the legacy layout and report `per-parameter`; callers can also
select that path with `reuse_buffers=False` (the default).

The packed path requires `torch.no_grad()` or `torch.inference_mode()`, sequential
layer execution, and unshared parameter storage. It rejects CUDA Graph capture
and state-dict operations while active. Disable the handle before changing
model dtype/device or saving/loading weights. For in-place edits use
`layerwise_offload_mutation_scope(layer)`; `handle.disable()` restores CPU weights
and removes hooks. Packed slots are a memory/copy-management option, not a
promise of higher throughput for every layer size.

The core `scaled_dot_product_attention` uses grouped query heads with zero-stride
K/V views for equal-batch 4D tensors and shared masks when explicitly selecting
`backend="efficient"`, or adapting an older SDPA without `enable_gqa`. Batch- or
head-specific masks retain explicit head expansion. Shape and layout can still
require a reshape copy. Existing native GQA selection remains unchanged.

The local measurements below used synthetic component probes with warmup
excluded, CUDA-event timings, and peak allocated memory. They are not
end-to-end model FPS. The design was
informed by FlashDreams [#637](https://github.com/NVIDIA/flashdreams/pull/637),
[#632](https://github.com/NVIDIA/flashdreams/pull/632), and
[#634](https://github.com/NVIDIA/flashdreams/pull/634).

A local component measurement on 2026-09-18 used one H100 80GB, PyTorch
2.5.1+cu121, FP16, 10 warmups and 50 measured rounds per fresh process:

| Probe | Median CUDA time | Peak allocated memory |
| --- | ---: | ---: |
| Offload, legacy per-parameter copies | 0.932 ms | 37.38 MiB |
| Offload, packed reusable slots | 1.514 ms | 37.38 MiB |
| GQA, explicit K/V head copies | 0.419 ms | 82 MiB |
| GQA, grouped views | 0.358 ms | 19 MiB |

Offload used eight 1024-wide Linear layers, batch 64. GQA used
Q `[1,32,256,64]`, K/V `[1,8,8192,64]`, and the efficient SDPA backend.
Packed offload halved H2D copy calls but was slower for these small layers, so
it stays opt-in. Measure the actual model and its layer sizes before selecting
it. Peak memory includes all live tensors in the process; it is not just weights.

## Evoke KV arena

Following FlashDreams [#635](https://github.com/NVIDIA/flashdreams/pull/635),
`KVSegmentArena` allocates contiguous `[static | current | memory]` K/V storage.
Persistent segments are copied once; subsequent steps only write the current segment.
Attention sees exactly the valid token count. Persistent views must alias the actual
arena segment, including storage, offset, stride, dtype, and device.

Ordinary Evoke inference self-attention supports this path, disabled by default.
Enable it on the native transformer:

```python
transformer.eval()
transformer.enable_kv_cache(use_arena=True)
# Baseline: transformer.enable_kv_cache(use_arena=False)
```

The preference survives subsequent no-argument `enable_kv_cache()` calls from the pipeline.
History keys enter the arena after their existing RoPE; positional encoding,
attention math, and eviction policy stay with the model.
Clearing/disabling the cache or running a first denoising step drops the old arena;
changing the current chunk length rebuilds it. Callers must still start a new first
step or clear the cache when history content or its RoPE changes.
Autograd, NAViT, sequence sharding, history amplification, and `torch.compile`
retain their existing paths. Each session/layer owns a separate arena, consumed
and updated sequentially on one CUDA stream.

The comparison used batch 1, 16 heads, head dimension 64, 4096 history tokens,
and 256 current tokens. Primitive cases add 1024 memory tokens; Evoke has no
memory segment.
The real Evoke attention module includes projections, normalization, RoPE, cache
handling, and output projection with random weights. Separate measurements covered
first-step rebuilds and Evoke's default 40-head, 128-dimension configuration.

On 2026-09-18, H100 80GB, PyTorch 2.5.1+cu121, FP16, 10 warmups and 50 rounds:

| Probe (cache reuse step) | Median CUDA time | Peak allocated | `aten::cat` per step |
| --- | ---: | ---: | ---: |
| KV assembly + SDPA, cat | 0.078 ms | 47.08 MiB | 2 |
| KV assembly + SDPA, arena | 0.045 ms | 27.08 MiB | 0 |
| Evoke attention, cat | 0.915 ms | 116.65 MiB | 4 |
| Evoke attention, arena | 0.819 ms | 100.15 MiB | 2 |

Evoke's remaining concatenations assemble attention outputs. The first step still
computes history KV and builds the arena, so reuse-step savings do not directly
translate into whole-request savings. Other GPU workloads were present; timings
are local observations, while allocated memory is specific to this process.
External FlashAttention 3 was unavailable, so Evoke used the PyTorch SDPA fallback.
These measurements exclude pretrained full-model quality and end-to-end FPS;
arena use remains opt-in.

With the same token counts, BF16 and 40 heads × 128 produced these single-layer results:

| Phase | Cat median CUDA time | Arena median CUDA time | Cat peak | Arena peak |
| --- | ---: | ---: | ---: | ---: |
| Cache reuse | 1.785 ms | 1.553 ms | 596.09 MiB | 513.59 MiB |
| First-step rebuild | 8.192 ms | 8.164 ms | 774.06 MiB | 776.56 MiB |

Reuse-step transient peak fell by 85 MiB, but resident allocated memory increased
from 403.43 to 405.93 MiB. The first step saved no peak memory and had very similar
timing. The extra 2.5 MiB of resident storage accumulates per layer, so the single
layer's 82.5 MiB peak reduction cannot be treated as a whole-model memory reduction.
Use `--layers 40` to measure sequential attention layers with all their caches resident;
this excludes MLPs, residual blocks, the VAE, and pretrained weights.

With 40 resident layer caches and the same BF16, 40 heads × 128 and token counts:

| Implementation | Median CUDA time | Peak allocated | `aten::cat` per step |
| --- | ---: | ---: | ---: |
| Cat | 90.858 ms | 13218.38 MiB | 160 |
| Arena | 80.479 ms | 13233.38 MiB | 80 |

Time decreased by about 11.4% in this measurement, but resident storage increased
by 100 MiB while transient peak fell by 85 MiB, increasing total peak by 15 MiB.
The arena therefore remains an optional throughput optimization; single-layer
results do not justify enabling it as a general memory-saving optimization.
Shared-GPU timings still require verification with the actual model and deployment load.

All 47 arena tests passed, including exact FP16/BF16 multiblock and multistep parity,
real 40 × 128 attention, RoPE replacement, empty history, chunk resizing, session
isolation, training fallback, cache clearing, and CUDA graph replay of the arena primitive.
The targeted regression suite, including GQA, offload, NVTX and SDPA compatibility,
passed all 77 tests. Full-model CUDA Graphs, external FlashAttention 3, and pretrained
video quality were outside this validation.
[Raw measurements and per-round samples](/measurements/kv-arena-2026-09-18.json)
preserve all ten cases.

## FlashDreams review and correctness gates

The 2026-10-03 review uses NVIDIA FlashDreams commit
`91c906b69992f63fb19907a25cd805fb783d314a`. WorldFoundry already provides
low-precision GEMMs, QKV fusion, fused normalization/RoPE, compilation,
CUDA Graphs, streaming/tiling VAEs, asynchronous offload, and distributed
attention. The additions address specific gaps in execution and correctness:

| Addition | Public surface and verified boundary |
| --- | --- |
| Fused GELU and FP8 activation quantization | `QuantizationPolicy.options["fuse_fp8_ffn"] = True`; matching Linear/GELU/Linear blocks, dense fallback, real FP8, Inductor and graph replay |
| Mixed VAE convolution layouts | `vae_channels_last=True` for Conv2d and `vae_channels_last_3d=True` for Conv3d, applied before compilation; weight identity, pixels and recurrent caches checked |
| MG2 causal optimizations | QKV fusion, managed cache positions, original FP16 decoder weights, and optional `overlap_vae_decode=True`; [model-specific contracts](/docs/guides/supported-models/matrix-game-2) |
| Dense TMA attention | Explicit core dispatcher `backend="triton_tma"` or `NativeAttention(backend="triton_tma")`; SM90+, FP16/BF16, no masks, GQA or backward; default backend selection is unchanged |
| Native cuDNN FP8 attention | `native_cudnn_fp8_sdpa` consumes already quantized E4M3 Q/K/V and explicit positive host descales, returning dequantized BF16; the shared model loader does not implicitly quantize BF16 attention inputs |
| CUDA frame transport to NVENC | `WORLDFOUNDRY_REALTIME_NVENC=1`; only supported uint8 RGB CUDA frames with the identity postprocessor retain device storage; producer events, packing, lifetime, codec negotiation and cleanup tested |
| Distributed step admission | `streaming_step_control(owner)` borrows a separate, bounded Gloo control group; real two-rank stop/reset/failure tests; production Studio generators are not yet wired to this primitive |

These additions are opt-in. TMA is not uniformly faster across shapes. Native
FP8 attention and FFNs have approximation budgets; operator parity alone does
not establish generated-video quality. NVENC's actual H.264 encoding still
requires a supported GPU and PyNvVideoCodec; H100 transport tests verify CUDA
pixels and SDK contracts, because H100 has no NVENC engine.

Benchmarks check every denoising output before timing: shape, finite values,
pointwise error, relative L2 and RMSE. A CUDA Graph result requires actual
capture/replay receipts; a dense fallback cannot count as acceleration.
Changing weights or precision policy invalidates captured graphs. Numerical
tests cover zero-padding boundaries, cache rewrites/rollover, previous-output
ownership, nondefault streams, cancellation, and failed-session cleanup.

```bash
# CPU contracts also run in hosted CI, without model checkpoints.
make test-infer-tensors PYTHON=python3

# Prepared SM90+ environment: CUDA Torch, Triton >=3.5, nvidia-cudnn-frontend,
# cuda-bindings, safetensors, einops and OmegaConf. Every selected case must
# execute and pass; unavailable CUDA and skipped cases fail this gate.
make test-infer-cuda-contracts PYTHON=python3

# Optional production-weight operator evidence; no downloads.
make test-mg2-checkpoint-contracts PYTHON=python3 \
  MG2_CHECKPOINT_ROOT=/checkpoints/Matrix-Game-2.0

# Full 30-layer model, original schedule/resolution; two exact trajectories.
make test-mg2-trajectory-contracts PYTHON=python3 \
  MG2_CHECKPOINT_ROOT=/checkpoints/Matrix-Game-2.0

# Real image VAE/CLIP conditioning, three seeds, and 141 frames for each QKV strategy.
make test-mg2-conditioned-trajectory-contracts PYTHON=python3 \
  MG2_CHECKPOINT_ROOT=/checkpoints/Matrix-Game-2.0
```

The checkpoint gate records full checkpoint, source, tensor and input hashes.
It exercises one production MG2 action block over eight cache writes, a real
1536→8960→1536 FFN at three amplitudes, and three consecutive streaming VAE
decodes. Initial H100 results: QKV outputs were bitwise equal, fused FP8 matched
the existing FP8 path, FP8 versus BF16 FFN relative L2 was 2.17%–3.01%, and VAE
layout changes differed by at most one RGB byte. The gate bounds these operators;
it does not certify public-prompt generation quality or throughput.
[Checkpoint hashes, acceptance budgets and per-step measurements](/measurements/flashdreams-mg2-2026-10-03.json)
retain the numerical evidence with portable source and checkpoint filenames.

The separate full-model trajectory gate requires bitwise equality for packed
and split QKV, managed cache positions, and decoder overlap against independent
legacy-cache/dense trajectories. It preserves the original warped schedule,
352×640 resolution, six-frame window and all 30 layers. Four blocks yield 45 RGB
frames and exercise two rolling boundaries. Every denoise/clean-refresh input,
flow, x0, final latent, generator cache, recurrent VAE cache and decoded pixel
must match exactly. [Recorded short-trajectory evidence](/measurements/mg2-trajectory-2026-10-03.json)
uses seeded image latents and visual embeddings; it excludes FP8, public-prompt
quality, long-horizon stability and performance.

The real-image conditioning gate also exercises public perception, VAE and CLIP
encoding, realtime configuration and generation. Image VAE weights convert
directly from the checkpoint to the requested dtype, avoiding an intermediate
FP16 rounding step. Resize reads the current request's canvas on every call;
the normalization transform can be reused across sizes.

Realtime blank conditioning cannot safely repeat the tail after only 15 latent
frames. The encoder's temporal receptive field is 113 RGB frames. Layer-by-layer
analysis places the first latent independent of the seed image and startup at
index 29. Three stable trailing latents require at least 32 latents, or 33 after
alignment to three-frame blocks: 129 RGB frames. Smaller prefetch settings are
raised to that minimum. The actual encoder structure determines the bound and
unknown temporal layers are rejected. The additional encoding occurs during
configuration; subsequent generation reuses the stable blank condition.

The new gate runs three seeds with both packed and split QKV at 352×640 using
the original schedule. Each trajectory generates 141 RGB frames and crosses ten
cache rollovers. Every model step, cache and pixel must equal an independent
directly encoded baseline bitwise. [Real conditioned trajectory evidence](/measurements/mg2-conditioned-trajectory-2026-10-03.json)
records checkpoint, source and input hashes. This does not certify public-prompt
quality, arbitrary durations or FP8.

Two upstream techniques require further model-specific work. Its native FP8
LightVAE is a calibrated OmniDreams encoder with 11 downsample blocks and
24/48/96 feature widths; neither MG2's full Wan2.1 FP16 decoder nor the existing
Wan2.2 48-latent-channel LightVAE is a compatible substitute. A matching model,
calibrated export and video-quality validation are required. MG2 full steady-state
CUDA Graph execution also remains rejected: absolute RoPE, growing action
windows and Python cache rollover must first be made replay-safe. The generic
graph runner and fixed-cache primitives do not by themselves remove these model
constraints.
Real CUDA Graph tests replay the fixed, full-window cache tensor body 18 times
per geometry; filling, Python position updates and rolling preparation stay eager.

## Migration checks for other models

The 2026-09-18 audit follows actual attention/cache paths. A cache may hold keys
before RoPE, keys after RoPE, or a linear-attention state matrix; these require
different storage and invalidation contracts.

| Model / path | Finding and action |
| --- | --- |
| **LongCat-Video, cached continuation** | Optional, disabled by default. When enabled, uses read-only batch broadcasting instead of history `repeat`, and RoPE on current queries only. Full keys retain their original positional rotation. No persistent arena is added. |
| **H-RDT, self/cross-attention** | Optional, disabled by default. When enabled, original KV heads reach core SDPA GQA; only the small V tensor needs unit-stride feature channels. Single-example padding uses a shared 2D mask view. Explicit cuDNN, cuDNN+efficient, and efficient-only per-example masks with multiple batch elements retain head expansion. |
| **HY-Embodied-VLA, MoT SDPA path** | Next candidate: `_sdpa_attention_forward_mot` still repeats K/V heads. Preserve visual segments, padding and causal masks. The dual-tower eager path has separate FP32 and finite-negative-mask semantics. |
| **Zing** | Self-attention concatenates raw historical K/V and rotates full keys each step. Investigate reserved storage and within-block static RoPE, including active/final commits, prompt switches, sink/pinned blocks and pruning. |
| **Gamma-World** | Causal attention already writes in place; focus on concatenation in `disable_kv_cache_update` and sink/window paths. A list-cache wrapper in the source tree does not prove the current inference entry uses it. |
| **LingBot-World, Self-Forcing, RCM, MoVerse fused memrope** | Fixed buffers or equivalent reuse already exist. RCM inference sets `fast_infer=True` and calls `write_transient`; avoid retaining a second history arena. Other MoVerse RoPE/EMA paths need separate analysis. |
| **Echo Infinity** | Window positions and relative RoPE change. Persisting rotated historical keys requires invalidation by window/position version; measure re-rotation first. |
| **Galaxea-VLA, Xiaomi-Robotics-1** | Not direct migrations: Galaxea applies soft-capping and mixture semantics; Xiaomi combines grouped historical KV with full-head current KV. Simply deleting repeats changes the contract. |
| **Sana linear attention** | Primarily caches recurrent state matrices. State updates and fused kernels are more relevant than a token KV arena. |

Further packed-offload candidates include **Wan 2.1/2.2, HunyuanVideo, Cosmos,
LTX and Sana**, whose native components declare a `layer_container`. The shared
loader does not enable `reuse_buffers=True` by default, and the earlier small-layer
benchmark did not establish a general speedup. Measure actual layer sizes, dtype,
quantization and CPU/GPU bandwidth. Models using `NativeDiffusionRunner` already
share NVTX ranges; custom autoregressive runners need instrumentation for their own phases.

Both optimizations are **disabled by default and can be enabled independently**.
They preserve the mathematical computation, but H-RDT's floating-point layouts
do not guarantee bitwise equality. Pretrained full-model quality validation is
still outstanding for both models; component parity does not certify quality.

| Environment variable | Default / disabled | Effect when enabled |
| --- | --- | --- |
| `WORLDFOUNDRY_HRDT_GQA_OPTIMIZATION` | Unset or `0` | `1`: enable H-RDT GQA storage optimization |
| `WORLDFOUNDRY_LONGCAT_KV_OPTIMIZATION` | Unset or `0` | `1`: enable historical KV broadcasting and current-query RoPE in LongCat |

Generation commands and prompts remain unchanged. Set the relevant variable before launch:

```bash
# Choose independently per model. Use 0 or unset the variable to disable.
export WORLDFOUNDRY_HRDT_GQA_OPTIMIZATION=1
export WORLDFOUNDRY_LONGCAT_KV_OPTIMIZATION=1
```

Variables are read when constructing the model. Reload the model after changing
them; persistent services need a reload or restart. Disabling restores the original
head expansion, four-dimensional padding mask and LongCat batch repeat / full-query
RoPE paths. Direct attention-module construction also accepts
`enable_gqa_optimization=False/True` or `enable_kv_optimization=False/True`,
respectively; explicit arguments override the environment. Evoke KV arena and
packed offload retain their separate disabled defaults.

The historical component comparisons explicitly disabled or enabled each
optimization, overriding environment settings. They used efficient SDPA with
16 Q / 4 KV heads for H-RDT, and 16 heads with the FA3-unavailable SDPA fallback
for LongCat. Both use head dimension 64, 256
query tokens, 4096 condition/history tokens, BF16 and random weights, with 10
warmups and 50 measured rounds in fresh processes. LongCat's benchmark grid
`(1, 1, 256)` controls the token count; it is not a video-resolution or full-model FPS test.

The measurements below were taken after stopping the GPU load process `gg` and
confirming idle GPUs, on an H100 80GB with PyTorch 2.5.1+cu121. Times are median
CUDA-event durations; peak memory is PyTorch allocated memory for the component process.

| Component / case | Before → after | Time reduction | Peak memory: before → after |
| --- | --- | --- | --- |
| H-RDT cross-attention, no mask, B=1 | 0.451 → 0.427 ms | 5.4% | 67.00 → 62.00 MiB (−5.00 MiB) |
| H-RDT cross-attention, padding mask, B=1 | 0.592 → 0.573 ms | 3.2% | 69.01 → 62.00 MiB (about −7.00 MiB) |
| LongCat cached continuation, B=2, shared B=1 history | 1.044 → 0.902 ms | 13.6% | 322.20 → 240.20 MiB (−82.00 MiB) |

Persistent allocated memory is unchanged in all three pairs. LongCat reduces
