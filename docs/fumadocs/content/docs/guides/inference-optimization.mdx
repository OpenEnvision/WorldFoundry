<Callout type="warn" title="Experimental">
These optimizations are experimental. They may change, may not apply to every model, and should not be treated as a supported production contract.
</Callout>

WorldFoundry only treats a technique as available when a public control exists and the main path consumes it. An accepted flag is not a speedup. After a forward, read `requested / effective / fallbacks` from `runtime_optimization_report()`.

[Pluggable diffusion acceleration](/docs/guides/diffusion-acceleration) covers the Sol-Engine / FlashDreams comparison, native SANA/Wan adapters, removal and request isolation, and configurations accepted or rejected by complete video diagnostics.

Most named knobs below are on the **native Wan 2.1 / Wan 2.2** pipelines (`Wan2p1*`, `Wan2p2*`, including VACE). Wan 2.5 / 2.6 / 2.7 are hosted APIs and have no local kernel controls. Other native recipes share only a subset (dtype, offload, sometimes attention or VAE tiling). Family runtimes (LTX, CogVideoX, and the rest) keep their own flags — do not copy Wan keys onto them.

<Callout type="info" title="Accepted is not effective">
Missing kernels, calibration, process groups, or checkpoint weights fail at build time or report an explicit dense / SDPA fallback. Wrapper installation alone (`*-wrapper-installed (runtime-pending)`) is not acceleration.
</Callout>

## Default recommendation

<Callout type="idea" title="First run vs throughput">
**First run / official-looking output.** Keep the catalog defaults: `torch_dtype="bfloat16"`, `offload_mode="resident"` when VRAM fits (Studio default for Wan2.2 TI2V-5B), otherwise `async-block`. Leave feature cache, approximate attention, quantization, CUDA Graph, and TAEW preview off. Do not cut steps or CFG for an official benchmark.

**Throughput on the same checkpoint.** Stay resident BF16. Set `attention_backend` to a real Flash / Sage provider for your GPU, then `fuse_qkv=True`, `fused_rope=True`, and `static_cross_kv=True`. Select `compile=True` at load time, then warm the representative requests before serving — the first compiled forward is slow. Turn on Wan VAE spatial tiling / temporal chunks if decode OOMs or dominates latency. Add **one** feature-cache algorithm only if you accept skipped DiT steps.
</Callout>

## What you can do

These controls are wired. Enable them from `from_pretrained(...)`, Workspace **load JSON**, or `worldfoundry-eval run --pipeline.load.<kebab-name>` when that key is on the model’s load schema.

### Representative request warmup

`pipeline.warmup([DiffusionRequest(...)])` executes complete native requests:
text/image conditioning, every sampler step, active CFG branches, routed experts,
and decode. It restores RNG state, releases request caches on success or failure,
and retains no output tensors. Successful warmup freezes CUDA Graph capture;
unseen serving signatures bypass CUDA Graph until another explicit warmup.
PyTorch may still compile new tensor shapes when compile is enabled. Calling the
pipeline normally without warmup retains lazy capture behavior.

For Studio resident workers, `warmup_requests` is a load option accepted by
`from_pretrained` and `--load-json`. It accepts a nonempty list of request
mappings or explicit nested batches of mappings, with `sampling` expressed as a
JSON object. Python callers may also
supply native `DiffusionRequest` objects. The pipeline is cached only after
loading and warmup succeed. Returned public pipelines expose
`warmup_reports`; these are execution receipts, not performance certification.

```json
{
  "offload_mode": "resident",
  "compile": true,
  "compile_scope": "regional",
  "cuda_graph": true,
  "static_cross_kv": true,
  "warmup_requests": [{
    "prompt": "A boat crossing a calm lake.",
    "negative_prompt": "",
    "height": 256, "width": 256, "num_frames": 17,
    "sampling": {
      "num_inference_steps": 50, "guidance_scale": 5.0, "seed": 0,
      "scheduler_options": {"shift": 5.0}
    }
  }]
}
```

Match deployed geometry, batch size, condition lengths, inputs, sampler,
autocast and inference-mode settings; the small shape above is a preparation example, not a production
benchmark. Warmup supports native standard, masked-latent and Wan dual-expert
CFG strategies, including the built-in frozen-latent mask extension. Custom
runners/extensions require their own lifecycle. Static-KV with Graph/regional
compile requires resident, unsharded
canonical Wan weights and the canonical cross-attention processor; memory
adapters and block/component offload are rejected. Change weights, LoRA or
placement by rebuilding the compiled/captured pipeline. Regional compilation
preserves model types and state-dict keys and reuses the persistent compile
cache. Regional Inductor uses `compile_mode="default"`, native GEMM dispatch,
and opaque native LayerNorm/RMSNorm reductions. Module hooks and autograd remain
intact. Shared compiled AdaLN and residual-gate operators retain native rounding,
including the mutating gate's alias contract. This trades reduction fusion and
GEMM autotuning for eager numerical boundaries.

`emulate_precision_casts=True`, `triton.codegen_upcast_to_fp32=False`,
`pattern_matcher=False`, and `epilogue_fusion=False` retain explicit dtype round
trips, `addmm`'s single rounding operation, and GEMM outputs before nonlinearities.
Conflicting precision options and regional GEMM autotuning are rejected.
Full-generation quality gates remain required for the target checkpoint,
precision, shapes, and PyTorch version. Compilation and Graph remain opt-in.

Use `python -m benchmarks.inference.wan_execution_preparation --checkpoint ...
--output-dir ...` for public-path dense/static-Graph/regional-static-Graph A/B/A
replays. Add `--model-id wan2.2-ti2v-5b` for 5B and `--images IMAGE_A IMAGE_B`
for changed-image masked-latent replay. Dual-expert cases use
`--model-id wan2.2-t2v-a14b` or `wan2.2-i2v-a14b` (the latter requires images).
`--dit-weight-dtype bfloat16` uses BF16 weights for both dense and candidate
configurations; compute remains BF16. Reports record observed parameter dtypes
and require current-request execution evidence from both experts.
`--configurations static-graph` selects that candidate alone; dense remains the reference and the report lists the
requested configurations. Add `--inplace-residual` to exercise candidates with
native mutating gates against the unchanged dense reference. This uses the existing native
quality budget, additionally requires bitwise latent parity for static-Graph,
reports RGB equality separately, and checks actual frozen-Graph replay. Its timings are diagnostic only.

### Compatible request batches

`pipeline.run_batch(requests)` accepts explicit `DiffusionRequest` values and
returns one independently owned `DiffusionOutput` per request, in input order.
It supports resident canonical Wan T2V, I2V and frozen-first-frame TI2V with
standard or dual-expert guidance and native Euler or Wan UniPC. Geometry,
sampling policy, scalar inputs and image-conditioning presence must match;
prompts, negative prompts, seeds, images and audit metadata may differ. Product defaults
and aliases from `pipeline(...)` are not applied to these normalized requests.

Each request keeps its original noise draw shape, generator, conditioning,
solver history, initializer artifacts and decoder call. Block projections and
FFNs use the combined batch; time MLPs, CLIP condition projections, attention
reductions and output heads retain original request shapes. This preserves
native rounding, including SDPA's shape-dependent split-KV dispatch. No sampler
or compute precision changes are made.

```python
from dataclasses import replace
from worldfoundry.base_models.diffusion_model.contracts import DiffusionRequest, SamplingConfig

request_a = DiffusionRequest(
    prompt="A small boat crossing a calm lake at sunrise.",
    negative_prompt="", height=256, width=256, num_frames=17,
    sampling=SamplingConfig(num_inference_steps=8, guidance_scale=5, seed=11,
                            scheduler_options={"shift": 5.0}),
)
request_b = replace(request_a, prompt="A dog running through a green field.",
                    sampling=replace(request_a.sampling, seed=29))
pipeline.warmup([request_a, (request_a, request_b)])
output_a, output_b = pipeline.run_batch((request_a, request_b))
```

For an image-conditioned pipeline, give each request its own image through
`inputs={"images": "/path/to/image.jpg"}`. Native TI2V retains the frozen-first-frame
mask extension; an all-text TI2V batch remains valid, but cannot mix with
image-conditioned requests. Both standard and dual-expert I2V retain request-local
image encoding and sampling state.

An explicit tuple inside `warmup` prepares a merged batch. Warm the deployed
row partition as well as total batch size; requests containing multiple prompts
retain their own row counts. Capture warms the actual static buffers, including
normalized layouts of expanded or sliced inputs, before entering CUDA Graph.
Each output's `metadata["request_batching"]` identifies its row range and the
shared batch ID, sample/request counts and observed denoiser calls. Denoiser
optimization receipts describe the whole batch, not independent request timings.

Add `--request-batching` to `benchmarks.inference.wan_execution_preparation` for
Wan1.3B, 5B TI2V or A14B T2V/I2V A/B, B/A, A/B batches against independent dense
requests. Image-conditioned replays require `--images IMAGE_A IMAGE_B`. The
existing latent/RGB quality budget also applies to batches. Reports retain
per-output quality, dispatch receipts, warmup time/peak allocated and reserved
memory, and diagnostic batch timings. `batch_comparison` compares the same two
requests using per-case singleton medians versus median batch time; it does not
certify performance on shared GPUs.

For normal product arguments, `pipeline.batch_call([call_a, call_b])` accepts
keyword mappings with the same defaults and aliases as `pipeline(...)`. Each
mapping can specify its own `output_dir` or `output_path` and `return_dict`.
Export paths must be distinct. Native sampling still uses `run_batch`; exports
and returned results remain request-local.

### Studio resident queue batching

Enable compatible coalescing before starting Workspace:

```bash
export WORLDFOUNDRY_STUDIO_BATCH_MAX_SIZE=2
export WORLDFOUNDRY_STUDIO_BATCH_DELAY_MS=5
```

The size defaults to **1** (ordinary singleton dispatch). The collection window
defaults to **5 ms**; a full batch or incompatible next request ends it early.
The existing Workspace job pool admits concurrent jobs (default 8 via
`WORLDFOUNDRY_WORKSPACE_MAX_JOBS`); at least two are needed to coalesce requests.
The resident worker still has one execution owner and keeps its request lock.
Only a compatible FIFO prefix merges, up to the configured request cap.

Admission covers single-prompt fresh `run` jobs for `wan2.1-t2v-1.3b`,
`wan2.2-t2v-a14b` and `wan2.2-ti2v-5b`. Select `offload_mode="resident"` (or
`"none"`) and `attention_backend="torch"`. Compilation, when selected, must use
`compile_scope="regional"`. Use `rope_precision="fp64"`,
`rms_norm_precision="fp32"`, `fuse_qkv=False` and `fused_rope=False`; explicitly
override the 5B Studio precision defaults. Model/loading options, geometry and
sampling policy must match; prompts, negative prompts, seeds and export paths
may differ.

For 5B image jobs, select one PNG/JPEG/BMP/WebP through Workspace's input picker
(`input_path`). Image paths may differ; image and text-only jobs do not merge.
Explicit image aliases in call JSON retain singleton dispatch. Other requests
also use serial singleton dispatch. Reconfigure these limits by restarting
resident workers.

Load-time `warmup_requests` accepts normalized request mappings and explicit
nested request lists: `[request_a, [request_a, request_b]]` warms both singleton
and two-request signatures. Include deployed geometry, sampler, CFG and original
row partitions. These are native request mappings, not product-call kwargs.

Each job retains its own run directory, `RunRecord`, artifacts and status.
`metadata.result.metadata.request_batching` records actual native batching;
`metadata.studio_request_batching` maps Studio records to that shared execution.
`studio_performance.resident_queue_wait_ms` covers the resident queue, excluding
GPU admission and worker startup. `batch_load_ms` and `batch_execute_ms` are
batch-wide host wall times; execution includes export. They are not per-request
GPU timings and must not be summed across members.

Queued cancellation removes work before execution. Cancelling or timing out an
active member stops delivery of its result without interrupting live or queued
peers; its computation may finish, and a produced manifest is marked cancelled.
An abandoned active batch with no remaining peers retires the worker. Execution
or export failure fails the selected batch without singleton retries. Worker
failure also fails queued jobs; subsequent submissions acquire a new worker.

**Limitations:** serialize direct singleton, batch and warmup calls on each
pipeline. Custom attention processors and extensions other than the native
frozen mask, approximate caches, offload and distributed batching are outside
this batch contract. Failed/cancelled jobs may leave diagnostic artifacts; no partial
results are returned for a failed batch. Choose the cap from measured VRAM
headroom: there is no OOM retry at a smaller batch size. Qualification remains
checkpoint/shape/precision specific; shared-GPU timings do not certify
throughput gains.

### Preview decode only

`vae_preview_decoder_path` swaps the Wan2.2 48-channel official VAE for TAEW2.2. That is a fast, approximate, decode-only preview. Official VAE tiling, temporal chunking, and VAE-parallel do not apply because the official decoder is not built. Do not use TAEW for final-quality or official-benchmark videos.

- **QKV / RoPE / static-KV** — a real call this request. Static-KV: hits, `bypasses=0`.

The standard `NativeDiffusionRunner` emits `worldfoundry.run`, `encode`,
`denoise_step`, `denoiser.positive/negative`, and `decode` ranges. The shared
video postprocessor and H.264 writer emit `worldfoundry.postprocess` and

## Reusable offload buffers and GQA compatibility

Opt in through the Python helper `enable_layerwise_cpu_offload(..., reuse_buffers=True)` to pack
contiguous weights by dtype into aligned CPU buffers and reuse at most two CUDA
slots. CUDA events prevent overwriting a slot while compute still reads it.
Its report includes `buffer_mode` and `device_buffer_bytes`. Non-contiguous
weights preserve the legacy layout and report `per-parameter`; callers can also
select that path with `reuse_buffers=False` (the default).

The packed path requires `torch.no_grad()` or `torch.inference_mode()`, sequential
layer execution, and unshared parameter storage. It rejects CUDA Graph capture
and state-dict operations while active. Disable the handle before changing
model dtype/device or saving/loading weights. For in-place edits use
`layerwise_offload_mutation_scope(layer)`; `handle.disable()` restores CPU weights
and removes hooks. Packed slots are a memory/copy-management option, not a
promise of higher throughput for every layer size.

The core `scaled_dot_product_attention` uses grouped query heads with zero-stride
K/V views for equal-batch 4D tensors and shared masks when explicitly selecting
`backend="efficient"`, or adapting an older SDPA without `enable_gqa`. Batch- or
head-specific masks retain explicit head expansion. Shape and layout can still
require a reshape copy. Existing native GQA selection remains unchanged.

The local measurements below used synthetic component probes with warmup
excluded, CUDA-event timings, and peak allocated memory. They are not
end-to-end model FPS. The design was
informed by FlashDreams [#637](https://github.com/NVIDIA/flashdreams/pull/637),
[#632](https://github.com/NVIDIA/flashdreams/pull/632), and
[#634](https://github.com/NVIDIA/flashdreams/pull/634).

A local component measurement on 2026-09-18 used one H100 80GB, PyTorch
2.5.1+cu121, FP16, 10 warmups and 50 measured rounds per fresh process:

| Probe | Median CUDA time | Peak allocated memory |
| --- | ---: | ---: |
| Offload, legacy per-parameter copies | 0.932 ms | 37.38 MiB |
| Offload, packed reusable slots | 1.514 ms | 37.38 MiB |
| GQA, explicit K/V head copies | 0.419 ms | 82 MiB |
| GQA, grouped views | 0.358 ms | 19 MiB |

Offload used eight 1024-wide Linear layers, batch 64. GQA used
Q `[1,32,256,64]`, K/V `[1,8,8192,64]`, and the efficient SDPA backend.
Packed offload halved H2D copy calls but was slower for these small layers, so
it stays opt-in. Measure the actual model and its layer sizes before selecting
it. Peak memory includes all live tensors in the process; it is not just weights.
