Open Dreamer is an open reimplementation of the Dreamer 4 interactive world model (paper arXiv 2509.24527): a diffusion world model that plays Minecraft-style scenes forward from a context clip and VPT-format actions. In this catalog the JAX source is never vendored — upstream publishes an all-rights-reserved notice — so WorldFoundry drives a user-staged checkout as a subprocess.

## What it is for

Pick `open-dreamer` when you need an action-conditioned world stepper: recorded actions and a frame in, a rollout out. Use it for interactive world inference, not a text-to-video prompt dump.

The WorldFoundry adapter is authored glue only: it resolves the staged checkout, gates on staging requirements, and builds the official inference.py command. WorldFoundry interaction tokens are rendered into Minecraft/VPT action JSONL so the shared world-model call surface drives the Dreamer 4 action space.

Catalog tasks include interactive-world-model, minecraft-world-model, action-conditioned-video, and diffusion-world-model. Catalog aliases include `open_dreamer`, `opendreamer`, `dreamer-4`, and `dreamer4`.

Recorded evaluation entry points include [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Action-conditioned world-rollout quality).

The catalog launch is `worldfoundry-eval run open-dreamer --pipeline.task-profile default`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.
