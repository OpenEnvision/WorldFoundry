NVIDIA DreamZero is a world-action model (WAM) that couples video prediction with robot control: DROID and AgiBot checkpoints are released under Apache-2.0 (GEAR-Dreams org). WorldFoundry keeps the inference-only model, preprocessing, distributed server, WebSocket client, and a pickle-free NumPy msgpack protocol in-tree; both checkpoints passed GPU probes on a CUDA 12.9 runtime.

## What it is for

Pick `dreamzero-droid` for world-action modeling: world-conditioned observations in, predicted actions out. Use it when the catalog marks a WAM route rather than a pure VLA or video model.

The default 14B server uses two CUDA ranks while the Wan2.2 5B entrypoint can run on one. Checkpoint-controlled Hydra targets are rewritten to and allowlisted within in-tree inference modules, so checkpoint Python is never executed. It is published by NVIDIA (GEAR Lab).

Catalog tasks include wam, world action model, wam world action modeling, and robot policy. Catalog aliases include `dreamzero-droid`, `dreamzero-agibot`, and `DreamZero-DROID`. Also recorded: `dreamzero-agibot`.

Recorded evaluation entry points include [EWMBench](/docs/evaluation/benchmark-hub/ewmbench) (World-action modeling quality for embodied control).

## Runtime contract

Optional `prompt`, `input_path`, `interactions`, `fps`, and `checkpoint_dir`; artifacts `dreamzero_action_trace.json`.

CLI task profiles: `interactive-video`. WorldFoundry binds `DreamZeroPipeline`.

Start on `dreamzero-droid`. The family registers 2 catalog variants (cards above): `dreamzero-droid` (`wam.world_action_modeling`) — Runner parity pending; `dreamzero-agibot` (`wam.post_training_base`) — Runner parity pending. Family status: **Runner parity pending**.

Stage DreamZero-DROID or DreamZero-AgiBot under WORLDFOUNDRY_HFD_ROOT; a CUDA 12.9 runtime is required. Choose DROID for real-robot arm data distribution and AgiBot for the AgiBot embodiment.

DreamZero DROID and AgiBot checkpoints are staged under $\{WORLDFOUNDRY_HFD_ROOT\}; the default 14B server uses two CUDA ranks, while the Wan2.2 5B entrypoint can use one.

## Running in WorldFoundry

The catalog launch is `worldfoundry-eval run dreamzero-droid --pipeline.task-profile interactive-video`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the dedicated environment `worldfoundry-dreamzero-cu129` (Python 3.11, CUDA 12.9, torch==2.8.0).

Recorded weight repositories include `GEAR-Dreams/DreamZero-DROID`, `GEAR-Dreams/DreamZero-AgiBot`, and `GEAR-Dreams/DreamZero-DROID` among others. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh dreamzero-droid`. Add `--download` to fetch missing public checkpoints.

Recorded licenses include apache-2.0; status: **Runner parity pending**.
