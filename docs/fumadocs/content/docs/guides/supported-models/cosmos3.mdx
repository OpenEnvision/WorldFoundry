Cosmos 3 is the **newest** Cosmos generation: one **omnimodal** world model that jointly handles text-to-image, text-to-video, image/video-to-video, **synchronized sound**, and structured action inference (**policy**, **forward dynamics**, **inverse dynamics**). Variants are `cosmos3-nano` and `cosmos3-super`. The earlier generations have their own pages: [Predict 2](/docs/guides/supported-models/cosmos-predict-2), [Predict 2.5](/docs/guides/supported-models/cosmos-predict-2.5), and [Transfer 2.5](/docs/guides/supported-models/cosmos-transfer-2.5).

WorldFoundry runs it **natively** — joint-modality runner, Karras **flow-UniPC**, Wan **VAE38**, inference-only **AVAE** sound decoder. Weights come from the official Hugging Face repos (`nvidia/Cosmos3-Nano`, `nvidia/Cosmos3-Super`) under **OpenMDW-1.1** and are **not gated**. Paper: [Cosmos 3: Omnimodal World Models for Physical AI](https://arxiv.org/abs/2606.02800). Project: [research.nvidia.com/labs/cosmos-lab/cosmos3](https://research.nvidia.com/labs/cosmos-lab/cosmos3/).

Validated on **Nano**: the released transformer, VAE38, and AVAE weights load completely, and the 35-step UniPC schedule matches the official solver numerically.

## What it is for

Use Cosmos 3 when one stack must cover image, video, optional sound, and structured action heads. Default launch is `wf run cosmos3-nano` with `--pipeline.task-profile t2v`. The `actions` field accepts `policy`, `forward_dynamics`, `inverse_dynamics`. Artifact: `cosmos3-nano.mp4` (family default `cosmos3.mp4`).

Pick `cosmos3-super` only when you intend the Super checkpoint. This infer-only recipe **excludes** Reasoner, training, guardrails, and vLLM / vLLM-Omni serving. For gated T5 video2world use Predict 2. For verified text-to-world at 1280×704 / 93 frames use Predict 2.5. For edge-controlled sim-to-real use Transfer 2.5.

Score world-generation quality on [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) and [Physics-IQ](/docs/evaluation/benchmark-hub/physics-iq).

## Running in WorldFoundry

`Cosmos3Pipeline` needs the **dedicated** environment `worldfoundry-cosmos3-cu128` (Python 3.11, CUDA 12.8, **torch==2.10.0**). It does **not** ride the unified cu128 profile that Predict / Transfer use. Base selection routes to Nano. The expected checkpoint revisions are Nano `411f42a8fdfb8c5b2583cb8786e0938f49796eaa` and Super `e0262be9d8f7586bc24c069a2aed2b665bdff266`; `prepare_model_infer.sh` reports the staged revision and pins the snapshot so an older local directory is not mistaken for the current release.

The native transformer matches the official `nvidia/Cosmos3-Nano` and `nvidia/Cosmos3-Super` parameter layout. Diffusers is not needed at runtime.
