DM0 是 Dexmal 的 Dexbotic 家族 flow-matching VLA：Qwen3 flow 动作专家，合并前后缀注意力与三视角预处理。仓库记录 base 与 LIBERO 两个 checkpoint（Dexmal/DM0-base、Dexmal/DM0-libero，CC 许可），完整推理环路——归一化加 Euler 采样器——在进程内从本地 checkpoint 运行。

## 用来做什么

用 `dm0` 做本卡的视觉-语言-动作推理。这条配方用来启动已记录的策略 profile。

基于 Qwen3 的 flow 动作专家配 Euler 采样器解码动作；Perception Encoder 与多模态基座复用兼容的树内 DB-CogACT 实现，保持 Dexbotic 家族一致性。

catalog 记录的任务包括 视觉-语言-动作（VLA）、VLA 动作预测、VLA 策略执行。别名包括 `dexbotic-dm0`、`dm0-base`。

记录的评测入口包括[LIBERO](/zh/docs/evaluation/benchmark-hub/libero)（有专门的 DM0-libero 策略 checkpoint）。

## 运行时契约

可选 `prompt`、`input_path`、`interactions`、`fps`、`timeout_seconds`；产物 `action_trace`、`dm0_action_trace.json`。

CLI task profile：`default`。绑定的 pipeline 类是 `DM0Pipeline`。

系列状态：**Runner 一致性待确认**。

LIBERO 评测用 DM0-libero，初始化用 DM0-base。 训练、数据集、服务、基准启动器与可选的 Triton 实时后端均被排除。

checkpoint 为 CC 许可——商业部署前请审查条款。

权重：`Dexmal/DM0-libero`（套件）与 `Dexmal/DM0-base`（初始化），在 `$WORLDFOUNDRY_HFD_ROOT` 下。状态：`checkpoint_ready`。**没有**记录 GPU rollout 验证。Perception Encoder 复用树内 DB-CogACT 栈。

## 在 WorldFoundry 中运行

catalog 启动命令是 `worldfoundry-eval run dm0 --pipeline.task-profile default`。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8，torch>=2.6.0）。

记录的权重仓库包括 `Dexmal/DM0-libero`、`Dexmal/DM0-base`。准备环境并检查本地资产：`bash scripts/inference/prepare_model_infer.sh dm0`；下载缺失的公开权重时加 `--download`。

状态：**Runner 一致性待确认**。
