VMem is an interactive video scene generation model with a surfel-indexed view memory: as you navigate a scene, it remembers which surfaces were seen from where, keeping new views consistent with the past. ## What it is for

Use `vmem` for catalog world-model inference. Choose it when you need action-conditioned future frames rather than a standalone clip generator.

VMem indexes past views by surface elements (surfels) and retrieves only the relevant ones to condition generation of the next view (per the publication, arXiv 2506.18903). The route depends on CUT3R as its geometry backbone; both checkpoints must be staged. It is published by University of Oxford.

Catalog tasks include video-generation, memory, stream, and interactive-world-model. Documented outputs include video.

Recorded evaluation entry points include [WorldScore](/docs/evaluation/benchmark-hub/worldscore) (Scores camera-navigable generated scenes).

## Running in WorldFoundry

The catalog launch is `worldfoundry-eval run vmem --pipeline.task-profile interactive-video`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `liguang0115/vmem`, `liguang0115/cut3r`, and `SagiPolaczek/stable-diffusion-2-1-base` among others. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh vmem`. Add `--download` to fetch missing public checkpoints.
