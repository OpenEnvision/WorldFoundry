[Show-o: One Single Transformer to Unify Multimodal Understanding and Generation](https://arxiv.org/abs/2408.12528) (ICLR 2025, 2024)

Show-o (Xie et al., Show Lab at NUS with ByteDance, arXiv 2408.12528) is a single 1.3B transformer that unifies multimodal understanding and generation. It is initialized from Phi-1.5 and, unlike systems that attach a separate diffusion expert to an MLLM, uses one set of weights for both.

Text is discrete tokens modeled autoregressively (next-token prediction). Images are MAGVIT-v2 lookup-free tokens — a 256×256 frame becomes a 16×16 grid from an 8,192-entry codebook — then generated by MaskGIT-style discrete diffusion (mask-token prediction) with full attention. Omni-attention is causal on text and bidirectional on image tokens. The LLM itself encodes the text condition, so there is no extra T5/CLIP text encoder.

The same checkpoint, in the paper, does VQA and captioning, text-to-image, and text-guided inpainting or extrapolation without extra finetuning, plus mixed-modality sequences. Default generation numbers use 1.3B parameters and about 35M image-text pairs (MSCOCO FID-30K 9.24), close to a LLaVA-v1.5-Phi-1.5 understanding-only baseline. In this catalog only the T2I wrapper is wired; MMU, inpainting, and extrapolation remain future work.

## Architecture

The transformer is Phi-1.5 with QK-Norm on every attention layer. The embedding table grows by 8,192 learnable image-token rows. A unified prompt wraps the sequence with task markers [MMU] / [T2I], text bounds [SOT]/[EOT], and image bounds [SOI]/[EOI]. Training mixes mask-token prediction and next-token prediction (L_MTP + α L_NTP). Generation starts from all [MASK] tokens and iteratively unmasks over T steps — about 20× fewer steps than autoregressive image decoding; the in-tree runtime defaults to 256 px, CFG 3.0, and 18 steps.

Image I/O uses the MAGVIT-v2 VQ tokenizer (showlab/magvitv2). The paper also studies continuous MAGVIT or CLIP-ViT features for understanding (Show-o† / Show-o‡); the released default and these catalog weights use discrete tokens for both understanding and generation. WorldFoundry's runtime lives under synthesis/visual_generation/show_o with a mode/prompt/image contract and microsoft/phi-1_5 plus showlab/show-o.

## Runtime contract

The verified WorldFoundry route is T2I only — set mode accordingly and expect a generated_image artifact. Paper-default resolution is 256; the wrapper uses classifier-free guidance (default 3.0) and 18 discrete-diffusion steps. Weights are MIT at showlab/show-o, with MAGVIT-v2 and Phi-1.5 as recorded companions. Image understanding and editing modes exist in the paper but are not wired here.

## Typical uses

- Text-to-image generation (wired)
- Visual question answering and captioning (paper; not wired)
- Text-guided inpainting and outpainting (paper; not wired)
- Mixed-modality interleaved generation (paper)

## Readiness and limitations

- Only text-to-image is wired; MMU, inpainting, and extrapolation remain future work.
- This entry produces images, not video.
- The published default is a 1.3B Phi-1.5 model at 256px discrete tokens, not a video backbone.
