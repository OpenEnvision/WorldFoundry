## What it is for

`motionbricks` is the recorded interactive world line. Start here when the job is stepping a world with actions.

Architecture internals beyond the recorded tasks are not stored in this repository (apache-2.0); the source is bound from the GR00T-WholeBodyControl repository at a pinned commit. The recorded artifact type is action_trace.

Catalog tasks include human-action-generation, motion-generation, and world-model.

## Runtime contract

Artifacts `action_trace` and `motionbricks_runtime_plan.json`.

CLI task profiles: `default`. WorldFoundry binds `MotionBricksPipeline`.

Family status: **Runner parity pending**.

Config resolution and pipeline import are expected to pass; real generation emits a runtime plan until required checkpoints/assets are staged. Missing assets are reported by the plan and are not treated as catalog blockers.

MotionBricks official source route is registered; motion/robot assets are runtime-gated.

## Running in WorldFoundry

Launch `worldfoundry-eval run motionbricks --pipeline.task-profile default` to step the world. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint id is recorded on this card; follow the usage notes for staging. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh motionbricks`. Add `--download` to fetch missing public checkpoints.

Status: **Runner parity pending**.
