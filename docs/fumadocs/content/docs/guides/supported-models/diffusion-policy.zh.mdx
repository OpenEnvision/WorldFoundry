Diffusion Policy 将机器人动作生成建模为条件去噪：给定短观测历史，迭代去噪出未来动作序列，而不是回归一个均值。官方论文是 [Diffusion Policy: Visuomotor Policy Learning via Action Diffusion](https://arxiv.org/abs/2303.04137)（arXiv 2303.04137）。项目页：[diffusion-policy.cs.columbia.edu](https://diffusion-policy.cs.columbia.edu/)。代码在 [real-stanford/diffusion_policy](https://github.com/real-stanford/diffusion_policy)。

WorldFoundry 仅支持**低维 PushT** 版本。图像条件的 Diffusion Policy variant 不在树内。运行时从离线转换、完全解析的 primitive 配置加纯张量 state dict 重建发布策略。别名 `diffusion_policy`、`dp` 解析到此模型。

## 用来做什么

这是视觉运动**动作**基线，不是视频生成，也不是语言条件 VLA。必填输入是 `state`，**`state_dim` 20**、**`observation_history` 2**。该路由不接受图像、指令或 prompt。`DiffusionPolicyPipeline` 写出 `diffusion_policy_action_trace.json`。

可用于在同一套低维 PushT 契约下，对比扩散动作头与回归策略。需要 RGB 或语言输入时，请换用其他模型。

## 运行时契约

视野、`n_action_steps` 与去噪步数从转换后的 checkpoint 配置恢复。runtime profile 固定的是：观测布局 `batch_time_feature`、特征维 **20**、历史 **2**、`float32`，`predict_action` → `action_trace`。

仅接受以下可信转换生成的权重：

`${WORLDFOUNDRY_CKPT_DIR}/embodied_action/diffusion-policy/low_dim_pusht_diffusion_policy_cnn/epoch=0550-test_mean_score=0.969.weights-only.ckpt`

文件名里的 `0.969` 是**上游文件名**的一部分，不是 WorldFoundry 分数。官方 dill workspace checkpoint 会在运行时被拒绝，没有不安全反序列化回退。环境里故意不装 `dill`。已用转换后的 checkpoint 验证：以 weights-only 方式重载、严格恢复 model / EMA，并在 A100 上输出有限的动作探针结果。

## 在 WorldFoundry 中运行

独立环境 `worldfoundry-diffusion-policy`（Python 3.10，CUDA 11.8 或更新）。就位转换后的 checkpoint，然后：

```
wf run diffusion-policy
```

没有可下载的 Hugging Face checkpoint，仅接受上述转换文件作为权重。未标注许可证；生产使用前请确认上游条款。
