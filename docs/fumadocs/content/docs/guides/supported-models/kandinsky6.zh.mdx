Kandinsky 6.0 从文本生成同步的视频与 44.1 kHz 音频，也可使用首帧图像作为条件。WorldFoundry 通过原生 diffusion recipe 注册表提供六个官方快照：

| Model ID | 网络 | 采样器 | 默认步数 |
| --- | --- | --- | --- |
| `kandinsky6-pro-distill` | Pro，29B | PiFlow | 10 |
| `kandinsky6-pro` | Pro，29B | Flow matching + CFG | 50 |
| `kandinsky6-pro-pretrain` | Pro，29B | Flow matching + CFG | 50 |
| `kandinsky6-lite-distill` | Lite，3B | PiFlow | 10 |
| `kandinsky6-lite` | Lite，3B | Flow matching + CFG | 50 |
| `kandinsky6-lite-pretrain` | Lite，3B | Flow matching + CFG | 50 |

`kandinsky6` 与 `kandinsky-6` 选择 `kandinsky6-pro-distill`。默认输出为 121 帧、24 fps、864×480，音频封装在 MP4 中。

## 运行

准备 `worldfoundry/data/models/runtime/environments/video/kandinsky6.yaml` 中描述的专用 Python 3.10 / CUDA 12.6 环境。该环境的依赖版本与使用真实 checkpoint 的 GPU 验证一致。在其中安装 WorldFoundry，并下载完整的官方 Diffusers 快照，包括两个文本编码器、tokenizer、两个 VAE 和 vocoder。

```python
from worldfoundry.pipelines.kandinsky6 import Kandinsky6Pipeline

pipe = Kandinsky6Pipeline.from_pretrained(
    "/path/to/Kandinsky-6.0-Pro-distill-5s-Diffusers",
    model_id="kandinsky6-pro-distill",
    device="cuda",
    offload_mode="component",
    attention_backend="sdpa",
)
result = pipe(
    prompt="A cat walks through a garden, birds singing in the background.",
    images="/path/to/first-frame.png",  # 可选的首帧图像条件。
    seed=42,
    output_path="outputs/kandinsky6.mp4",
    return_dict=True,
)
```

Pipeline 写出 MP4、JSON 运行报告以及保存编码后 prompt 的文本文件。`offload_mode="component"` 按完整模块调度权重，`"block"` 按 transformer block 调度，`"none"` 将全部权重留在所选设备上。宽高必须为 16 的正整数倍，帧数必须符合 `4*n+1`。

非蒸馏快照支持 `sample_audio=False`。蒸馏快照要求生成音频且 `guidance_scale=1.0`。未指定本地 checkpoint 时，组件通过 WorldFoundry 的原生 Hugging Face checkpoint resolver 获取。

## 架构

Transformer 与 PiFlow head 的实现位于 `base_models/diffusion_model/models/networks/kandinsky6`。Prompt 编码器和视频、音频 codec 分别由独立的组件模块负责。框架负责 checkpoint 准备、flow schedule、联合采样和 MP4 封装。推理无需外部源码 checkout 或上游 CLI。

官方源码：[kandinskylab/kandinsky-6](https://github.com/kandinskylab/kandinsky-6)，revision 为 `b224b77cb458c2f9241a5a245bedc4fd43817b11`。源码采用 MIT 许可证，随附音频组件保留各自的许可证声明。

## CUDA 验证

固定版本的 `kandinsky6-pro-distill` 快照在一张 NVIDIA H100 80GB 上通过了文本生成视频验证，使用 SDPA、component offload、10 步和 seed 42。输出包含 121 帧、864×480、24 fps 视频及 44.1 kHz 音频。权重加载耗时 85.2 秒，生成耗时 140.4 秒。PyAV 检查确认了两个流、视频尺寸、帧数、采样率以及音频数值有限；首帧、中间帧和末帧展示了 prompt 描述的橘猫在花园中行走。

验证环境使用 Python 3.10.16、PyTorch 2.9.0+cu126、Diffusers 0.40.0、Transformers 5.14.1、Safetensors 0.8.0 和 PyAV 16.0.1。视频 VAE 选择空间 tile 时计入卷积 workspace，并保留边缘不足一个完整 tile 的区域。

```bash
python scripts/inference/check_kandinsky6.py \
  --checkpoint-dir ../ckpt/kandinskylab--Kandinsky-6.0-Pro-distill-5s-Diffusers \
  --output-dir outputs/kandinsky6-pro-distill-validation \
  --offload-mode component --attention-backend sdpa
```

该命令写出 `output.mp4`、`cuda-validation.json` 和三张预览帧。报告包含依赖版本、加载与生成耗时、峰值 CUDA 内存、视频指标以及音频 RMS 和峰值。

## 限制

GPU 证据覆盖 Pro-distill 文本生成视频。图像生成视频、另外五个快照以及与官方 demo 的 parity 尚未验证；这五个 catalog 条目保留 `planned` 状态。CPU 测试覆盖普通与 PiFlow 原生 runner、请求规范化、本地 checkpoint 错误、空间 tile 边缘及 MP4 音视频流。独立的 Kandinsky 超分模型不属于该集成。
