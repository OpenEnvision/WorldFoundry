## Architecture

Per the paper (arXiv 2503.11647), ReCamMaster conditions a pre-trained text-to-video model (Wan-family in the open release) on the source video through frame-dimension conditioning, letting camera trajectories be swapped at generation time. Runtime execution requires local Wan2.1, the ReCamMaster checkpoint, torchvision, and CUDA assets.

## Runtime contract

The open-source reference runtime is checkpoint/GPU gated — no empty runner shim is registered. Stage Wan2.1 plus the ReCamMaster checkpoint before submitting jobs; per-run visual QA is tracked outside the catalog.

## Evaluation benchmarks

- [CameraBench](/docs/evaluation/benchmark-hub/camerabench) — Directly evaluates camera-trajectory control quality.

## Readiness and limitations

- Requires local Wan2.1 and ReCamMaster checkpoints plus CUDA.
- Re-rendering quality is bounded by the source video content — unseen regions are hallucinated.
