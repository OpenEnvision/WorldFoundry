## What it is for

Pick `rt-1` when you want the catalog VLA policy: instruction and observation in, an action trace out. Use it to roll the recorded policy, not to train a new one.

An EfficientNet-B3 image tokenizer with FiLM language conditioning, TokenLearner compression, and a decoder-only transformer emitting discretized action tokens — served as a TensorFlow SavedModel. It is published by Google Research.

Catalog tasks include vla, vla policy rollout, robot policy, and robotics transformer. Catalog aliases include `rt1` and `robotics-transformer`.

## Runtime contract

Required `input_path` and `language_embedding`; optional `prompt` and `plan_only`; artifacts `rt1_action_trace.json`.

CLI task profiles: `vla`. WorldFoundry binds `RT1Pipeline`.

Family status: **Runner parity pending**.

Supply a 512-D language_embedding from an encoder compatible with the checkpoint along with the image and prompt. The released SavedModel does not turn prompt text into that embedding; WorldFoundry rejects text-only inference instead of silently using zeros. GPU inference needs a TensorFlow/CuDNN-compatible environment.

The released SavedModel consumes a precomputed 512-D language embedding; passing only a prompt string is rejected because the SavedModel does not encode text.

## Running in WorldFoundry

Launch `worldfoundry-eval run rt-1 --pipeline.task-profile vla` to execute the policy. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CPU).

No public checkpoint id is recorded on this card; follow the usage notes for staging. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh rt-1`. Add `--download` to fetch missing public checkpoints.
