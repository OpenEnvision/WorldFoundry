title: Kandinsky 6.0
description: Native Lite and Pro audio-video generation with optional first-frame conditioning.
---

Kandinsky 6.0 generates synchronized video and 44.1 kHz audio from text, optionally conditioned on a first-frame image. WorldFoundry exposes six official snapshots through the native diffusion recipe registry:

| Model ID | Network | Sampler | Default steps |
| --- | --- | --- | --- |
| `kandinsky6-pro-distill` | Pro, 29B | PiFlow | 10 |
| `kandinsky6-pro` | Pro, 29B | Flow matching + CFG | 50 |
| `kandinsky6-pro-pretrain` | Pro, 29B | Flow matching + CFG | 50 |
| `kandinsky6-lite-distill` | Lite, 3B | PiFlow | 10 |
| `kandinsky6-lite` | Lite, 3B | Flow matching + CFG | 50 |
| `kandinsky6-lite-pretrain` | Lite, 3B | Flow matching + CFG | 50 |

`kandinsky6` and `kandinsky-6` select `kandinsky6-pro-distill`. The default output is 121 frames at 24 fps, 864×480, with audio muxed into the MP4.

## Run

Prepare the dedicated Python 3.10 / CUDA 12.6 environment described by `worldfoundry/data/models/runtime/environments/video/kandinsky6.yaml`. Its pinned dependencies match the checkpoint-backed GPU validation. Install WorldFoundry into that environment and download a complete official Diffusers snapshot, including both text encoders, tokenizers, both VAEs, and the vocoder.

```python
from worldfoundry.pipelines.kandinsky6 import Kandinsky6Pipeline

pipe = Kandinsky6Pipeline.from_pretrained(
    "/path/to/Kandinsky-6.0-Pro-distill-5s-Diffusers",
    model_id="kandinsky6-pro-distill",
    device="cuda",
    offload_mode="component",
    attention_backend="sdpa",
)
result = pipe(
    prompt="A cat walks through a garden, birds singing in the background.",
    images="/path/to/first-frame.png",  # Optional first-frame conditioning.
    seed=42,
    output_path="outputs/kandinsky6.mp4",
    return_dict=True,
)
```

The pipeline writes an MP4, a JSON run report, and a text sidecar containing the encoded prompt. `offload_mode="component"` stages whole modules; `"block"` stages transformer blocks. `"none"` keeps all weights on the selected device. Width and height must be positive multiples of 16; frame counts must follow `4*n+1`.

Non-distilled snapshots support `sample_audio=False`. Distilled snapshots require audio and `guidance_scale=1.0`. With no local checkpoint override, component acquisition uses WorldFoundry's native Hugging Face checkpoint resolver.

## Architecture

The canonical transformer and PiFlow head live in `base_models/diffusion_model/models/networks/kandinsky6`. Prompt encoders and video/audio codecs have separate role owners. The framework owns checkpoint materialization, flow schedules, joint sampling, and MP4 muxing. No external source checkout or upstream CLI is required at inference time.

Official source: [kandinskylab/kandinsky-6](https://github.com/kandinskylab/kandinsky-6), revision `b224b77cb458c2f9241a5a245bedc4fd43817b11`. Source licensing is MIT; bundled audio components retain their license notices.

## CUDA validation

The pinned `kandinsky6-pro-distill` snapshot passed text-to-video generation on one NVIDIA H100 80GB with SDPA, component offload, 10 steps, and seed 42. The output contains 121 frames at 864×480 and 24 fps, plus 44.1 kHz audio. Weight loading took 85.2 seconds and generation took 140.4 seconds. PyAV checks verified both streams, geometry, frame count, sample rate, and finite audio; first, middle, and last frames show the prompted orange cat walking through a garden.

The validated environment uses Python 3.10.16, PyTorch 2.9.0+cu126, Diffusers 0.40.0, Transformers 5.14.1, Safetensors 0.8.0, and PyAV 16.0.1. The video VAE accounts for convolution workspace when choosing spatial tiles and preserves partial edge tiles.

```bash
python scripts/inference/check_kandinsky6.py \
  --checkpoint-dir ../ckpt/kandinskylab--Kandinsky-6.0-Pro-distill-5s-Diffusers \
  --output-dir outputs/kandinsky6-pro-distill-validation \
  --offload-mode component --attention-backend sdpa
```

This writes `output.mp4`, `cuda-validation.json`, and three preview frames. The report includes package versions, load and generation times, peak CUDA memory, video metrics, and audio RMS and peak levels.

## Limitations

GPU evidence covers Pro-distill text-to-video. Image-to-video, the other five snapshots, and parity with the official demo remain unvalidated; those five catalog entries retain `planned` status. CPU tests cover ordinary and PiFlow native runners, request normalization, local checkpoint errors, spatial tile edge coverage, and MP4 video/audio streams. The separate Kandinsky super-resolution model is not part of this integration.
