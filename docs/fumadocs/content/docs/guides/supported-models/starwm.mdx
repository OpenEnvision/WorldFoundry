StarWM is a multi-agent world model for StarCraft-style environments: it predicts action-conditioned game video across many interacting units. WorldFoundry exposes the official offline inference client in-tree; jobs talk to an OpenAI-compatible StarWM endpoint using the official prompt fixture format, with the confirmed yxzhang2024/StarWM checkpoint on Hugging Face.

## What it is for

`starwm` is the recorded interactive world line. Start here when the job is stepping a world with actions.

The runtime is an endpoint-client design: the route builds the official run_inference_client.py command and validates input_file, mode, and served_model_id/api_model_id before execution. Model architecture internals are not recorded in this repository.

Catalog tasks include multi-agent-world-model, starcraft-world-model, and action-conditioned-video.

Recorded evaluation entry points include [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Action-conditioned game-world rollout quality).

## Runtime contract

Optional `load.input_file`, `load.served_model_id`, `plan_only`, and `timeout_seconds`; artifacts `generated_world` and `starwm_predictions.jsonl`.

CLI task profiles: `starcraft-offline-client`. WorldFoundry binds `StarWMPipeline`.

WorldFoundry exposes the official offline inference client in-tree under synthesis/visual_generation/starwm/offline_infer.

## Running in WorldFoundry

Launch `worldfoundry-eval run starwm --pipeline.task-profile starcraft-offline-client` to step the world. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `yxzhang2024/StarWM`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh starwm`. Add `--download` to fetch missing public checkpoints.
