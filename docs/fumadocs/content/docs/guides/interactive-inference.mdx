title: Interactive world model inference
description: Run Zing, Astronex-World, SolarWM, AlayaWorld v1.1 and Echo-WM with explicit inference-only routes.
---

These routes generate video using local weights. Catalog browsing and configuration checks work on CPU; generation requires CUDA. No weights are downloaded during inference. New integrations have CPU contract checks; GPU output quality and checkpoint-backed parity are still pending.

| Model ID | Inference route | Required source |
| --- | --- | --- |
| `zing` (alias `zing-0.5`) | Native Wan2.2 layers, UMT5, VAE38; Zing keyboard and causal cache extensions | None |
| `astronex-world` | Official causal or bidirectional sampler | Astronex-World checkout |
| `solarwm` | Official `solarwm infer`, indexed image/caption/camera cases | SolarWM checkout and matching backend environment |
| `alayaworld` | Existing native LTX-2.3 + DA3 merged checkpoint route | None |
| `alayaworld-v1.1` | Extracted inference-only ViGeo rollout, shared loaders/VAE/history/text and external Alaya transformer extension | AlayaWorld and ViGeo1.1 source |
| `joyai-echo-wm` | Official Base or Flash audio/video inference | JoyAI-Echo checkout |

Runtime settings live under `worldfoundry/data/models/runtime/configs/`. Training loops, optimizers, losses and data preparation pipelines are not part of these integrations. External checkouts stay outside the WorldFoundry source tree. SolarWM refers to upstream inference recipes without copying their mixed training/inference configuration trees.

## Workspace, TUI and CLI

All routes in the table are discoverable in Workspace and the TUI. The shared inference contract supplies model variants, input fields and loading options. Echo Base/Flash expose their own controls; SolarWM uses indexed data and does not ask for a prompt or image.

Inspect a model without loading checkpoints:

```bash
worldfoundry run zing --help
worldfoundry run solarwm --model-variant h3-ar --model-status
worldfoundry run joyai-echo-wm --model-variant flash --help
```

For direct inference, loading options use `--pipeline.load.*`; generation options use `--pipeline.*`:

```bash
worldfoundry run zing \
  --pipeline.load.checkpoint-dir /path/to/zing-0.5 \
  --pipeline.prompt "A walk through a quiet garden." \
  --pipeline.num-frames 81 \
  --output-dir tmp/zing
```

In the TUI, select the model and variant, then use **Model assets / loading (JSON)** for additional paths and **Inference options (JSON)** for model controls. For SolarWM, for example, supply `{"base_path":"/weights/base","data_root":"/data/index"}` in the loading field and `{"overrides":{"inference.sample_count":1}}` in the inference field. Set its checkpoint path separately. LTX and H3 routes also require the assets listed below.

## Zing-0.5

Stage `seedleap/zing-0.5` with its original `generator/model.pt` and `pretrained/{text_encoder,tokenizer,vae}` layout. Install the optional CUDA inference dependencies from the `zing` runtime environment manifest.

```python
from worldfoundry.pipelines.zing import ZingPipeline

pipe = ZingPipeline.from_pretrained("/path/to/zing-0.5", device="cuda")
result = pipe(
    prompt="A first-person walk through a quiet garden.",
    images="/path/to/first-frame.png",  # omit for text-to-video
    num_frames=81,
    height=480,
    width=832,
    controls=[{
        "type": "keyboard_direction_frame_interval",
        "actions": [[1, 0, 0, 0, 0, 0, 0, 0]] * 80,
    }],
    output_path="tmp/zing/result.mp4",
    return_dict=True,
)
pipe.close()
```

`num_frames` includes the reference frame and must equal `1 + 4*N`. Width and height must be multiples of 32. Keyboard lanes are **W, A, S, D, I, J, K, L**, with values in `[0, 1]`; supply `num_frames - 1` rows. Optional `text_prompt_interval` controls use the released segment format (`start`, `end`, `text`), covering the remainder of the pixel timeline without gaps or overlaps. Segment boundaries snap to the VAE latent grid as upstream does.

## Astronex-World

Use source revision `27584bf1a89da01ef35a03b48d83bc818d2adf2b` and the `Astronex-Lab/Astronex-World` checkpoint layout.

```python
from worldfoundry.pipelines.astronex_world import AstronexWorldPipeline

pipe = AstronexWorldPipeline.from_pretrained(
    checkpoint_dir="/path/to/Astronex-World-weights",
    source_root="/path/to/Astronex-World-source",
    python_executable="/path/to/astronex-env/bin/python",
    mode="causal",  # or "bidirectional"
    device="cuda:0",
)
result = pipe(
    prompt="A first-person view moving through a stone corridor.",
    images="/path/to/first-frame.png",
    latent_frames=23,
    trajectory="w*12,h*11",
    output_dir="tmp/astronex",
    execute=True,
    return_dict=True,
)
```

`latent_frames` counts generated **latent frames**, unlike Zing's pixel-frame setting. In causal mode, `(latent_frames + reference_count)` must be divisible by 8. Camera segment lengths must sum to `latent_frames`. Events use `event_prompt` and `event_start_frame` on the latent timeline. `action_tokens`, `action_keys`, `action_scale` and `embodiment_id` pass through to the official action conditioner. The shipped zero-initialized action-prediction head is not exposed as a trained predictor.

## SolarWM

Use source revision `2fe1ea9aca072f787bbba07ee9380b0e1ea7563b`. The public inference interface reads image, caption and camera trajectories from indexed samples; it is not a free-form prompt/image endpoint.

```python
from worldfoundry.pipelines.solarwm import SolarWMPipeline

pipe = SolarWMPipeline.from_pretrained(
    source_root="/path/to/SolarWM",
    python_executable="/path/to/solar-wan-env/bin/python",
    variant="wan-5b-dmd",
    base_path="/path/to/SolarWM-models/SolarWM-5B-base",
    checkpoint_dir="/path/to/SolarWM-models/SolarWM-5B-sgf-stage2-81f",
    data_root="/path/to/SolarWM-Data/releases-v1",
    device="cuda:0",
)
result = pipe(output_dir="tmp/solarwm", execute=True, return_dict=True)
```

Other variants are `wan-5b-dmd-237f`, `wan-5b-ar`, `wan-5b-bidirectional`, `wan-5b-bidirectional-153f`, `wan-14b`, `ltx`, `h3-bidirectional`, `h3-ar`, `h3-dmd` and `h3-dmd-long`. GPU process counts are recorded in `solarwm/routes.yaml`; explicit CUDA device lists must match them.

The `wan-5b-dmd-237f` route follows the indexed source length. Supply at least 237 video frames and matching camera poses to exercise its 237-frame rollout; selecting this variant with an 81-frame source still produces an 81-frame clip.

Wan, LTX and H3 require **separate environments**. The packaged `solarwm` environment describes the default Wan route only. Follow the pinned upstream environment guide for LTX/H3, and pass its Python interpreter explicitly. LTX needs `assets` entries `model.codec.video_vae_path` and `inference.negative_caption_cache`. H3 needs `data.silence_latents_path` and `data.encoder_contract_path`; `h3-dmd-long` additionally needs `inference.plan` and `inference.dataset_root`. These are existing inference assets; this integration does not preencode data.

Use `overrides={"data.test_index": "...", "validation.sample_count": 1}` for Wan indexed selection. LTX uses `data.index` and `inference.sample_count`. Unknown overrides and training commands are rejected. Each call gets a fresh output directory. Completed videos and completion markers are required before a run is reported successful.

SolarWM code is Apache-2.0. LTX and H3 checkpoints retain their respective community licenses, including H3 territory restrictions.

## AlayaWorld v1.1

Keep the original `alayaworld` merged checkpoint separate. Version 1.1 requires the stage2b transformer/history, LTX-2.3 base checkpoint, unquantized Gemma and ViGeo1.1. DMD additionally loads the stage3 LoRA. Use AlayaWorld source revision `ea03cfbb2e4c4e9102ed8ea8562e0b5370ca9b79` and the matching ViGeo release.

```python
from worldfoundry.pipelines.alayaworld_v11 import AlayaWorldV11Pipeline

pipe = AlayaWorldV11Pipeline.from_pretrained(
    source_root="/path/to/AlayaWorld",
    python_executable="/path/to/alaya-env/bin/python",
    checkpoint_dir="/path/to/AlayaWorld-v1.1-stage2b",
    student_dir="/path/to/AlayaWorld-v1.1-stage3",
    base_checkpoint="/path/to/ltx-2.3-22b-dev.safetensors",
    gemma_path="/path/to/gemma-3-12b-it-qat-q4_0-unquantized",
    vigeo_checkpoint="/path/to/ViGeo1.1",
    vigeo_source_root="/path/to/ViGeo",
    variant="dmd",  # "ar" uses 30 steps and no student adapter
)
result = pipe(
    prompt="A first-person walk through an ancient courtyard.",
    images="/path/to/first-frame.png",
    camera_path="/path/to/camera-c2w.npy",  # [F,4,4], or .npz / .txt
    rounds=5,
    output_dir="tmp/alayaworld-v11",
    execute=True,
    return_dict=True,
)
```

Omit `camera_path` to synthesize the released forward trajectory; optional `forward`, `yaw`, `pitch` and normalized `intrinsic=[fx, fy, cx, cy]` control it. A supplied camera path must be long enough for the requested rollout. The inference session includes no trainer class or setup/optimization lifecycle. It reuses the shared LTX VAE, text encoding, history encoder and checkpoint/LoRA loaders. The Alaya transformer extension and ViGeo geometry remain external dependencies. GPU memory and artifact parity are unvalidated; full-window VAE encoding may have higher peak memory than the upstream streaming encoder.

## Echo-WM

The existing `JoyAIEchoWMPipeline` supports `variant="base"` and `variant="flash"`. Use JoyAI-Echo revision `a08f1274573d7cd6ec66719f204951f4227a5173` and `Echo-Team/Echo-WM` weights.

```python
from worldfoundry.pipelines.joyai_echo.pipeline_joyai_echo import JoyAIEchoWMPipeline

pipe = JoyAIEchoWMPipeline.from_pretrained(
    source_root="/path/to/JoyAI-Echo",
    checkpoint_dir="/path/to/Echo-WM",
    gemma_path="/path/to/gemma-3-12b-it-qat-q4_0-unquantized",
    python_executable="/path/to/echo-wm-env/bin/python",
    variant="flash",
)
result = pipe(
    prompt="A quiet fantasy canyon with a clear river and birdsong.",
    images="/path/to/first-frame.png",
    action_str="w-120,none-120",
    num_frames=241,
    output_path="tmp/echo-wm/result.mp4",
    execute=True,
    return_dict=True,
)
```

Base prompts use the six upstream fields: Environment, Character, Style, Perspective, Sounds and Speech. Base lengths are `1 + 8*N`; Flash lengths are `1 + 8*video_chunk_size*N` (default chunk size 3). Audio is on by default; set `no_audio=True` for video only. Width/height must be multiples of 32. No long-horizon checkpoint availability or GPU parity is implied by catalog registration.
